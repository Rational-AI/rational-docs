# Give a touchpoint memory and handle long conversations

Out of the box, every conversation starts from zero: the assistant doesn't know that this person prefers short answers, or that your company calls its customers "members". And a conversation that runs long enough eventually outgrows what the model can read at once. The **Memory** tab of a [touchpoint](/operational-guides/configure-touchpoints) handles both: what the assistant carries from one conversation to the next, and what it does when a single conversation gets too long.

:::note[What is touchpoint memory?]
Memory is a short list of facts the assistant reads at the start of every conversation on the touchpoint. **Personal memory** is about one person and only they can open it. **Shared memory** is about everything else — the company, its customers, how things are named — and applies to everyone who uses the assistant. Memory holds facts only; how a task is done belongs in a [skill](/operational-guides/agent-skills).
:::

## Prerequisites

Before you start, make sure you have:

- **Permission to edit the touchpoint:** needed to switch memory on, to choose what happens with long conversations, and to curate shared memories.
- **A touchpoint to configure:** see [Configure touchpoints](/operational-guides/configure-touchpoints).

## Switch memory on

Both kinds of memory are off by default.

1. Go to **Settings** → **Touchpoints**, open the touchpoint and select the **Memory** tab.
2. Switch on **Personal memory**, **Shared memory**, or both.
3. If you turned on shared memory, choose under **New shared memories** what happens when the assistant learns something in a chat:

   | Option | When to use it |
   |--------|----------------|
   | **Wait for an editor's approval** | The default. Nothing reaches everyone until a person with edit rights approves it. |
   | **Save right away** | A trusted, internal assistant where speed matters more than review. |
   | **Only added by hand** | You want full control: the assistant reads shared memory but never adds to it. |

4. Save the touchpoint. The memories list appears once memory is on and saved.

While memory is on, the assistant gets a `memory` tool it uses to add, update and remove entries during a chat. Users see each change in the conversation — *"Remembered"*, *"Remembered for everyone"*, *"Proposed to the shared memory"*, *"Forgot"* — with **Undo** or **Withdraw** where it applies, and can switch memory off for a single chat.

:::note[Memory is kept short on purpose]
Each memory is at most 280 characters, a person's memory holds 1,500 characters in all, and the shared memory 3,000. Links, credentials and long or multi-line text are refused. When a store is nearly full, the assistant merges older memories rather than piling on new ones.
:::

## Curate shared memories

Shared memory speaks for everyone, so it is worth an editor's eye.

1. On the **Memory** tab, check **Waiting for approval**. Each proposal shows who proposed it and when.
2. Select **Approve** to add it to the shared memory, or **Discard** to drop it. The touchpoint's creator is notified of new proposals.
3. In **Memories**, filter by **All**, **Shared** or **Me**. Use a row's menu to **Edit** or **Delete** an entry, and the **Add a shared memory** field to write one yourself.

Curation applies immediately; it doesn't wait for the touchpoint's **Save**. Approvals, discards and deletions of shared memories are recorded in the audit trail.

:::note[Editors don't see anyone's personal memory]
A person's personal memories are theirs alone. The filter **Me** shows only your own, marked *"You · private"*. Editing rights on the touchpoint don't open anyone else's list, though whoever monitors conversations can still read the chats the memories came from.
:::

## Choose what happens when a conversation gets too long

A model can read only so much of a conversation at once. **Long conversations**, further down the **Memory** tab, decides what happens when a conversation gets there.

1. Open the **Long conversations** dropdown and choose:

   | Option | When to use it |
   |--------|----------------|
   | **Summarize the oldest messages and continue (recommended)** | The default. The assistant keeps a summary of the earlier part and the latest messages in full, and the conversation carries on. |
   | **Summarize, but keep some tool results word for word** | Some tool results must never be reworded — a patient record, a contract clause. Add those tools under **Keep word for word**; their results are copied into the summary exactly as returned. |
   | **Stop and ask to start a new conversation** | Nothing may be summarized. The user is told the conversation is full and can start a new one. |

2. Save the touchpoint.

:::note[When summarizing kicks in]
Rational AI summarizes before a turn when the previous request filled more than 85% of the model's context window, or when the provider rejects a request as too long. The most recent messages, roughly a quarter of the window, are kept word for word. Only what the model reads is shortened: the full history stays in the chat and in [Conversations](/operational-guides/conversations).
:::

In the chat, a divider marks where the summary begins: *"The assistant now works from a summary of the messages above"*. With **Stop and ask to start a new conversation**, the composer is disabled and the chat offers **New conversation** instead; the old conversation stays in the user's history.

## Result

Your touchpoint now remembers what you allow it to: each person's preferences privately, and shared facts once an editor approves them, or straight away if you chose so. Long conversations no longer fail when they outgrow the model: they continue from a summary, keep the tool results you marked word for word, or stop and point the user to a new conversation.

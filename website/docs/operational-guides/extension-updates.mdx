# Update and roll back extensions

Publishers ship new releases of their extensions with fixes, new tools, or new settings. Use the update policy to decide how much updates on their own, apply updates when you choose, and roll back to the last version that worked.

:::note[What is a release?]
A **release** is one version of an extension's package. A release never changes once published: a fix is always a new version. Your installation runs one release at a time, so the version you ran yesterday is still there to go back to.
:::

A solution installed from the [Marketplace](/operational-guides/marketplace) is an extension too, but it updates from its solution page, where you preview what changes in your Knowledge. See [Update a solution](/operational-guides/marketplace#update-a-solution).

## Choose an update policy

Open the extension on **Settings** → **Extensions** and choose its **Update policy**.

| Policy | What it does |
|--------|--------------|
| **Compatible updates automatically** | Compatible updates are applied for you. Breaking updates are listed but never applied on their own. |
| **Notify me** *(default)* | Available updates are listed, and nothing is applied until you apply it. |
| **Pinned** | The extension stays on this version. Even a manual update is refused until you change the policy. |

Available updates show under every policy. While an extension is pinned, the **Update** button is replaced by *"Pinned. Change the update policy to install updates."* You can still roll back a pinned extension.

Updates also pause while an extension is in development mode (see [Edit an installed extension's files](/operational-guides/manage-extensions#edit-an-installed-extensions-files)).

## Compatible and breaking updates

Rational AI compares each new release with the previous one. A release is **compatible** when your saved configuration still works with it and nothing your touchpoints use has gone: no tool or MCP server removed, no setting renamed or changed type, and no new required setting without a default. Anything else is **breaking**.

## Apply an update

1. Open the extension and select **Update** next to its version, or **Update to latest version** or **Install a different version** from the options menu.
2. In the dialog, pick the **Version** and read its **Release notes**. If the new release needs configuration values, fill them in.
3. Select **Update**.

Rational AI checks the update before changing anything. If a check fails, for example because a touchpoint still uses a tool or skill the new release removes, nothing changes and the dialog says why. **Force update** applies the update anyway and removes or disables what no longer fits, including those touchpoints' access to the removed tools. The checks appear in the extension's **Activity** tab marked **Review**.

If an update fails, the extension keeps running the release it was on, and the failure is recorded in its history. Supply what was missing and run the update again.

## Roll back

Select **Roll back** in the extension's options menu to return to the release marked **Last good** in its **Versions** tab. Rollback is available under every update policy, including **Pinned**.

## Withdrawn releases

Rational AI can withdraw a release that shipped a serious problem. A withdrawn release disappears from the catalog and from the updates offered to you, and can't be installed. If you already run it, it keeps running and stays in the extension's version history. Update to a newer release as soon as one is available.

## Uninstall

Uninstalling removes the extension, its MCP servers, its configurations and its tools. Touchpoints that used its tools stay and keep working without those tools. You can install the same package again later.

# Build an agent

An agent is only as good as its profile. The instructions say what the job is and how to do it; the tools say what it can touch; **Ask me first** says where it must stop and wait for you. This guide walks through the profile field by field, using **Quinn**, a quotation analyst who prices requests for quotation and must never write an offer without a person looking at it first.

:::note[The profile drives every run]
Whatever starts the agent (a task, a chat message, a schedule or a webhook), the run starts from the profile: its instructions become the system prompt, its model answers, and it can use only the tools granted there and the Knowledge it gives access to. Changing the profile changes the next run, not the ones already going.
:::

## Prerequisites

- **Access to the Agents section**: see [Rational Agents](/cr/Agents#prerequisites).
- **A text-generation model** in the [AI Model Registry](/operational-guides/ai-model-registry-features), or the platform Agents default.
- **Optional: extensions with tools.** Tools from installed [extensions](/operational-guides/manage-extensions) can be granted to an agent; the [Library](#browse-the-library) lists them all.

## Create the profile

1. In **Agents**, select **All agents** under *Team* in the sidebar to open the **Team** page, then select **New agent**.
2. The **New agent** panel opens. Enter the **Name** (required) and, optionally, a role (*Role (optional)*). The role is shown under the name everywhere the agent appears.

### Let a model draft it

Under **Draft with AI**, describe the job in a sentence and select **Draft with AI**. A model fills in the name, description, instructions, trigger, tools and which tools ask first; for a schedule it also proposes the cron expression and the time zone. Everything it writes stays editable, so treat it as a first draft. If the model cannot produce a usable draft you are told *"Couldn't draft this agent. Fill it in by hand."*

For Quinn, a good one-liner is: *"Price incoming requests for quotation from our price list, flag what we cannot make in-house and write the offer file, but ask me before writing it."*

### Describe it

- **What it does**: one line shown on the agent card, such as *"Turns incoming requests for quotation into priced, checked offers."*
- **Instructions**: *"The system prompt for every run. Context files are still appended at runtime."* This is where the job lives. Say what the agent receives, what it must produce and in what shape, what it must never do and how to report back. Quinn's say, among other things, *"Never invent prices or codes. Write the offer as a Markdown file offers/&lt;RFQ code&gt;.md … Always write in English."*

:::note[Write instructions for a result that can be checked]
Agents verify their own work before they finish: a run that produced a file, a record or a precise answer can be checked, a vague one cannot. *"Write the offer as offers/RFQ-….md with one row per line"* gives the agent, and you, a way to know it is done. An agent without instructions can be saved but not started: **Run now** and **Create and run** stay disabled until you add them.
:::

### Give it access to Knowledge

**Knowledge access** lists the Knowledge bases you can use. Select the ones this agent may search, and turn on **Can change** on a base to let the agent also add, edit and delete its resources, views and files. Quinn gets *Customer quotes*, the base with the price list, the plant capabilities and the quoting manual.

If you select none, a run can search every Knowledge base that the person who started it can use. Select at least one to keep the agent inside a boundary. A run that works on a project's task or chat can also use that project's Knowledge (see [Group tasks in projects](./agent-tasks#group-tasks-in-projects)).

### Give it secrets

**Secrets** lists the values an administrator added under **Settings** → **Agents**, such as an API token. Select the ones this agent's commands may read as environment variables; the agent sees their names, never their values. Anyone who can edit or prompt the agent can make it use or send its secrets, so grant only what the job needs.

### Pick the model

Under **Model**, keep **Platform default for agents** or choose a specific text-generation model. Every model goes through the platform gateway, so its calls are captured and governed like any other.

### Built-in tools

**Tools** are the file and shell tools the agent uses on its computer: `read`, `write` and `edit` for files, `grep`, `find` and `ls` to search and list them, and `bash` to run commands. Start from a preset and adjust:

| Preset | Tools |
|--------|-------|
| **Coding** (the default) | `read`, `bash`, `edit`, `write` |
| **Read-only** | `read`, `grep`, `find`, `ls` |
| **All** | all seven |

An amber dot marks the selected tools that write or execute (`bash`, `edit`, `write`). Knowledge access is independent of these tools: an agent with no built-in tools can still search the Knowledge it was given.

### Extensions and tools

**Extensions & tools** lists every tool from the installed extensions, grouped by extension, with a search box and a *granted* count. Select the tools this agent may call. A tool whose extension shows *Needs setup* (typically a missing connector) cannot be selected until that is fixed. A tool marked *Blocked by your admin* cannot be used, and one marked *Admin approval required* always asks first.

When the agent has email or messaging tools, two more fields appear: **Sends from** picks the Email channel its emails go out from (the replies come back to it), and **Writes on** picks the Telegram or WhatsApp channel it writes to people on. Without a mailbox the agent only drafts emails; without a messaging channel it sends no messages.

### Ask me first

**Ask me first** (*"These pause the run and wait for your approval on every call."*) lists every tool you granted, built-in or from an extension. Select the ones that must wait for a person. Quinn has `read` and `write`, and `write` is ticked: Quinn can read and compute freely, but every file it wants to write is shown to you first.

At the bottom of the panel, a summary puts the three levels side by side:

- **On its own**: the tools that run without asking.
- **Asks you first**: the tools you ticked.
- **Never**: anything outside the tools above.

:::warning[Grant the least, gate what changes things]
An agent can do anything its tools allow, as often as it decides to, on everything in its Knowledge scope. Give it only the tools the job needs, and put every tool that sends, writes or deletes under **Ask me first** until you have seen enough runs to trust it. See [Approve what the agent wants to do](./agent-runs#approve-what-the-agent-wants-to-do).
:::

**Identity** (chassis, color, sliders) only shapes the agent's avatar. It does not change how the agent behaves.

## Decide what starts it

**Trigger & execution**: *"What starts a run, whether it runs in the cloud, and whether you can steer it mid-run."*

- **Trigger**: **Manual** (the default, used by tasks, chats and **Run now**), **Schedule**, **API**, **Webhook**, **GitHub event**, **New email**, **New file** or **Record changed**. Every trigger except **Manual** is covered in [Schedule and trigger agents](./agent-routines).
- **Where**: keep **Cloud**. Runs execute on the agent's computer, which the platform runs for you.
- **Mode**: **Autonomous** agents work through the job on their own; **Interactive** agents are meant to be steered with messages while they work.

A run has 20 minutes to finish. Interactive agents, and agents with at least one tool under **Ask me first**, get six hours, so a run can wait for a person without timing out.

## Save and try it

- **Create agent** saves the agent. It appears on the **Team** page and in the sidebar roster.
- **Create and run** saves it and starts a run straight away. When you edit an agent, the same buttons read **Save** and **Save and run**.

Open the agent from the team page to see its profile at a glance: the model, the trigger, the mode, its computer, its tools and Knowledge, the instructions, its spend this month and the list of its runs.

<img
  alt="Quinn's profile page with Edit, Run now and Pause, the model and trigger summary, the running computer and the system prompt"
  src={require('@site/static/img/screens/agents-profile.png').default}
  style={{ maxWidth: '100%', borderRadius: 8, border: '1px solid #e5e7eb' }}

From here:

- **Run now** opens **Run &lt;name&gt;**. Write the **Goal for this run** (*"Describe a concrete outcome"*) and select **Start run**. The agent's instructions still apply; the goal is what this run must deliver. For a quick question, use a [chat](./agent-chats) instead.
- **Edit** reopens the profile panel. **Delete** is at the bottom of that panel; it asks for confirmation, and the agent's past runs are kept for audit.
- **Pause** stops the agent's triggers from starting runs; see [Pause an agent](./agent-routines#pause-an-agent).
- **More actions** has **Duplicate** and **Export** (a JSON file that **Import** on the **Team** page turns back into an agent).
- **Monthly budget** caps what the agent's model calls may cost each month. At 80% the owner is warned; once the budget is used, new runs are refused until you raise or remove it.
- **Runs** lists every run of this agent with **Cancel** for the ones still going and **Retry** for the most recent run that failed or timed out.

## Browse the library

**Agents** → **Library** lists every tool and skill you can grant to an agent.

<img
  alt="The Library page with 26 tools from five extensions: C-Parts Desk, Graphify Query, Rational Knowledge RAG Query Server, Vega charts and RationalAI Widgets"
  src={require('@site/static/img/screens/agents-library.png').default}
  style={{ maxWidth: '100%', borderRadius: 8, border: '1px solid #e5e7eb' }}
/>

- **Tools**: grouped by extension. Expand one to see its tools under the names the agent sees, which are also the names **Ask me first** matches. **Search a tool…** filters them, and **Read-only tools** keeps only those that change nothing. A *Needs setup* badge means the extension still needs a connector.
- **Skills**: the skills the installed extensions register for agents, with **Search a skill…**. These are not the skills people pick with `/` in Chat, which are set on a touchpoint (see [Use skills in chat](/operational-guides/agent-skills)).

Installing an extension gives its tools to nobody. A tool runs only for an agent that has it under **Extensions & tools**, and only on the Knowledge that agent can reach. To add tools, [install an extension](/operational-guides/manage-extensions).

## Troubleshooting

| Symptom | What to check |
|---------|---------------|
| **Run now** is grayed out | The profile has no instructions. Open **Edit** and write them. |
| The run fails with *"No text-generation model is available — add one to the registry first."* | There is no text-generation model in the AI Model Registry. Add one, or connect a subscription. |
| The run fails with *"The configured Agents default model is unavailable."* | The **Agents model** default points to a model that was removed or withdrawn. Pick another under **Default models**, or set a model on the agent. |
| The agent says a tool is not available | The tool is not granted on the profile, or its extension needs setup. Check **Extensions & tools** in the profile and the badges in the [Library](#browse-the-library). |
| Saving fails on the name | Agent names are unique. Pick a different one. |

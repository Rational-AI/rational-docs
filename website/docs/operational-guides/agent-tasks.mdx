# Delegate work with tasks

A task is a piece of work you hand to one or more agents and want to see finished: *"Prepare the offer for RFQ-2026-0153"*, *"Weekly sales report for week 39"*. The **Tasks** board shows every task in one of four columns, moves them on its own as the agents work, and brings to the front the ones that need you. This guide covers the board, the task itself and the projects that group tasks together.

:::note[Tasks and runs]
A task is the **what**; a run is one attempt at doing it. Starting a task opens a run with its first assignee, and the run's progress drives the task: while the run works the task is *Working*, when it needs an approval or fails the task goes into *To review*, when it completes the task goes to *Done* (or waits in *To review* when its project has a reviewer) and the agent's final answer is posted on it as a comment.
:::

## Prerequisites

- **At least one agent**: see [Build an agent](./create-an-agent). A task needs at least one agent on it.

## Read the board

Open **Agents** → **Tasks**.

  alt="The Tasks board: three tasks queued, two working, one done, with project tags, subtask counters and assignee avatars"
  src={require('@site/static/img/screens/agents-tasks-board.png').default}
  style={{ maxWidth: '100%', borderRadius: 8, border: '1px solid #e5e7eb' }}
/>

| Column | Means |
|--------|-------|
| **Queued** | Waiting to be started. New tasks land here. |
| **Working** | A run is going. The card shows what the agent is doing (*Agent is working*, *Waiting to run*) and its progress. |
| **To review** | The agent is waiting for your approval (*Waiting for your approval*), or the run ended without a verified result and the card says why. |
| **Done** | Completed. The agent's answer is in the task's comments. |

Each card shows the task name, its project, the subtasks done out of the total, the comment count and the avatars of its agents. The line under the title counts the tasks (*N tasks. Track progress and review results.*). The badge next to **Tasks** in the sidebar counts the tasks to review plus the runs waiting for an approval, each counted once.

To narrow the board, type in **Filter tasks…** or open **Filters**: **Updated** (**Today**, **Last 7 days**, **Last 30 days**, **All time**) and **Assignee** (**Everyone** or one agent). The project picker in the sidebar narrows it to one project. **List** shows the same tasks as a table you can group (by status, project or assignee), sort and filter by due date; **Calendar** opens the schedule view described in [Schedule and trigger agents](./agent-routines#see-whats-coming-in-the-calendar).

## Create a task

1. Select **New task**.
2. Under **What needs doing**, write the title on the first line and the details on the following lines. Put everything the agent needs to deliver a checkable result: the input, the expected output, the constraints. You can attach files (up to 10 MB each) or paste pictures into the text.
3. Choose a **Project**, or keep **No project**.
4. Under **Assign to**, pick the agent responsible for the task. To add more agents, select **Add collaborators**.
5. Select **Start now with &lt;agent&gt;** to start right away; otherwise the task waits in *Queued*.
6. Select **Create task**.

<img
  alt="The New task dialog with a two-line description, the project picker, Quinn selected as assignee and the Start immediately checkbox"
  src={require('@site/static/img/screens/agents-new-task.png').default}
  style={{ maxWidth: '100%', borderRadius: 8, border: '1px solid #e5e7eb' }}
/>

For a quick one, use **Add a task** in any column: type *What needs doing?*, pick an agent and select **Add**.

Tasks get a short key (`RA-1`, `RA-2`, …) that never changes. Agents can also open tasks themselves, for example a librarian agent that files one task for each outdated sheet it finds; those land in *Queued*.

## Start and move tasks

- **Drag a card** to another column, or reorder it within its column. Dragging a task to *Working* starts a run with its first assignee.
- In the task, select **Start with &lt;agent&gt;**, or choose a column from **Move to…**.

If the agent cannot be started (no model, missing permissions), the task goes into *To review* with *"Could not start the assigned agent. Check permissions, model and workflow availability, then retry."*

## Work inside a task

Select a card to open it.

<img
  alt="Task RA-5 open in To review: the RFQ description with the customer lines and the price list, subtasks, comments, and the Open live run action"
  src={require('@site/static/img/screens/agents-task-detail.png').default}
  style={{ maxWidth: '100%', borderRadius: 8, border: '1px solid #e5e7eb' }}
/>

- **Description**: what you wrote when you created it.
- **Subtasks**: a checklist with a progress bar; type in **Add a subtask…** and select the subtasks as they are done.
- **Comments**: the conversation on the task. When a run completes, the agent's final answer is posted here. Reply to the agent to continue the work, or mention an agent with `@` to put it to work.
- **Documents**: Word documents the agents produced for this task, with their version, their review state (*Agent-reviewed*, *Agent review outdated*, *Not agent-reviewed*) and their approval (*Approved*, *Not approved*). Select a document's name to edit it in the browser and **Save**, **Download** it, open its **Version history**, or approve the current version with **Approve v&lt;n&gt;**. If a document does not open for editing, ask Rational AI to enable in-browser editing on your installation.
- **Project**: move the task to another project, or leave it *Unassigned*.
- **Actions**: **Open live run** while a run is going (see [Follow runs and approve actions](./agent-runs)), **Approve** when a finished task waits for review, **Start with &lt;agent&gt;** otherwise, **Move to…** and **Delete task**.

When a run fails, the task shows **What it needs from you**, with **Retry** and **Reply**.

:::danger[Deleting a task cannot be undone]
**Delete task** asks for confirmation, then removes the task with its subtasks and comments.
:::

## Group tasks in projects

A project collects related tasks, chats and documents, and optionally points to the Knowledge base they are about. Open it from **Manage projects** next to the project picker, or go to **Agents** → **Projects**.

<img
  alt="The Projects page with two projects, Market intelligence and Customer quotes, the second linked to its Knowledge base"
  src={require('@site/static/img/screens/agents-projects.png').default}
  style={{ maxWidth: '100%', borderRadius: 8, border: '1px solid #e5e7eb' }}
/>

1. Select **New project**. Give it a **Name**, a **Description** and, optionally, a **Knowledge** base.
2. Choose a **Reviewer**, or keep **No review: finished tasks go to Done**. With a reviewer, a task an agent finishes waits in *To review* until a person approves it.
3. Select **Create project**.

Each card shows how many tasks are done and open, how many are to review, the linked Knowledge and the reviewer. **Project settings** has **Change Knowledge…** and **Change review step…**, and **Open tasks** opens the board filtered to that project. Selecting a project in the sidebar picker does the same for the whole section.

Agents projects are separate from [Rational BI](/operational-guides/rational-bi) projects.

:::note[A project's Knowledge reaches its agents]
A run that works on a task or chat of a project is told about the project's Knowledge base and can search and change it, even when the agent's **Knowledge access** does not list it. The person who started the run must be allowed to use that Knowledge. Everything else the agent may touch is set on its profile.
:::

## Who sees a task

A task is visible to everyone who can see at least one of the agents assigned to it.

# Manage extensions

Extensions add capabilities to Rational AI, such as MCP servers your agents can call. This guide covers managing and installing extensions in the UI: making them available in the registry, installing them into your tenant, and reading what each extension card tells you.

<Admonition type="info" icon="📖" title="WHAT IS AN EXTENSION?">
An extension is a bundle that adds a capability to Rational AI, most commonly one or more MCP (Model Context Protocol) servers. Making an extension *available* uploads it to the shared registry; *installing* it adds it into your tenant. These are two separate, explicit steps.
</Admonition>

<Admonition type="note" icon="📝" title="LOOKING TO BUILD AN EXTENSION?">
This guide is about managing and installing extensions in the UI. To create your own extension and its manifest, see the extension authoring guide.
</Admonition>

## Prerequisites

Before you start, make sure you have:

- **Administrative access:** an account with extension management privileges.
- **The extension bundle (if uploading your own):** a `.tar.bz2`, `.zip`, `.mcpb` file, or a bare `manifest.json`. The format is auto-detected.
- **Any required configuration values:** for remote (HTTP) MCP servers, the endpoint URL and authentication token or header the server expects.

## Read the extension card

Each extension is shown as a card on the **Extensions** page.

- The **version** from the manifest is shown next to the extension name, so you can see the installed version at a glance.

## Make an extension available

Uploading a bundle to the registry makes it available for anyone to install. Nothing is installed locally by this step.

1. Go to **Settings** → **Extensions**.
2. Drag an extension bundle from your file system and drop it anywhere on the page. A dashed drop overlay appears while you drag.
3. Release the file to upload it. A toast confirms the extension is now available.

The list of installed extensions is unchanged by this step; the bundle is only added to the registry.

<Admonition type="note" icon="📝" title="ACCEPTED FILES AND CONFLICTS">
Accepted bundles are `.tar.bz2`, `.zip`, `.mcpb`, or a bare `manifest.json`. Dropping an unsupported file shows a warning toast and nothing is uploaded. Re-uploading a bundle whose name identifier and version already exist in the registry surfaces a conflict as an error toast.
</Admonition>

You can also drag a bundle directly onto the registry list inside the **Add extension** dialog. The bundle is added to the registry and the new entry is selected automatically.

## Install an extension into your tenant

1. Go to **Settings** → **Extensions** and select **+ Add**.
2. In the registry picker, browse the available extensions. The detail pane shows the first non-installed extension automatically, so it is never blank.
3. Select the extension you want, then confirm to install it into your tenant.

<Admonition type="note" icon="📝" title="ALREADY-INSTALLED EXTENSIONS ARE SHOWN">
Extensions you have already installed stay visible in the registry list, rendered **disabled** and not selectable, with an **Already installed** tag. This lets you see what is already added without being able to re-select it.
</Admonition>

## Configure remote (HTTP) MCP servers

Extensions can include MCP servers reached over HTTP (streamable-HTTP or SSE), not just local ones spawned as a process. A single extension can bundle both local and remote servers.

1. Open the extension's **details** page.
2. In the **MCP servers** section, review each server. A remote server shows a **Remote** chip and its endpoint URL; a local one shows a **Local** chip.
3. For a remote server that requires authentication, enter the token or header value in the extension-configuration form. The value comes from your configuration and is never stored in the manifest. Headers that resolve to empty are dropped, so a public no-auth server sends no blank header.

<Admonition type="note" icon="📝" title="READY-MADE REMOTE EXTENSIONS">
Rational AI ships ready-to-use remote MCP extension manifests for many connectors (for example GitHub, Linear, Atlassian, monday, Airtable, Supabase, Snowflake, Sentry, PagerDuty, Shopify and more). Each takes an endpoint URL plus an authentication header from your configuration. A generic **remote-mcp** extension lets you add any remote MCP server by supplying its URL and an optional `Authorization` header.
</Admonition>

## Result

You can read each extension's version from its card, upload bundles to make extensions available, and install them into your tenant from the **Add** dialog, where already-installed extensions stay visible but disabled. For extensions with remote MCP servers, you can identify them by the **Remote** chip and endpoint URL and supply their authentication through the extension-configuration form.

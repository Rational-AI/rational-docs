# Manage extensions

Extensions add capabilities to Rational AI: tools your agents can call, skills, channels, sources and workflows, and the complete use cases that [Marketplace](/operational-guides/marketplace) solutions install. Use this guide to install an extension from the catalog or from a file and configure it so it starts running. To keep an installed extension current, see [Update and roll back extensions](/operational-guides/extension-updates).

:::note[What is an extension?]
An extension is a package that adds capabilities to Rational AI. Many extensions provide one or more MCP servers. MCP (Model Context Protocol) is an open standard for connecting AI agents to tools and data, so an MCP server is a set of tools your agents can call. Other extensions are Marketplace solutions that set up a Knowledge with its views and records, agents and BI dashboards.
:::

Installing an extension and configuring it are separate steps. An installed extension starts running only once it is configured.

## Where extensions come from

- **Rational AI catalogue**: the releases Rational AI publishes, the same for every workspace.
- **Local**: packages you installed from a file. Only your workspace sees them.
- **Remote sources**: third-party registries Rational AI can attach for your organization. Their packages appear alongside the others.

## Prerequisites

Before you start, make sure you have:

- **Administrative access:** an account with extension management privileges.
- **The extension package (only if you're installing your own):** a `.tar.bz2`, `.zip` or `.mcpb` file, or a bare `manifest.json`.
- **Any required configuration values:** for remote MCP servers reached over the network, the endpoint URL plus whatever authentication token or header the server expects.

## Read an extension card

Every installed extension appears as a card in the **Installed** view of the **Extensions** page. The card shows the extension's version next to its name, and **Configuration needed** when the extension's server still needs parameters, **Update available** or **Review required** when a newer release exists, and a switch to turn the extension on or off.

## Install an extension from the catalog

1. Go to **Settings** → **Extensions** and select **Install**.
2. Browse the available extensions. Each is marked **Rational AI catalogue** or **Local** (a package uploaded to your workspace).
3. Select the extension you want, then **Configure extension**.
4. If the extension runs an MCP server, fill in the **Set default configuration** form: API keys, connection strings, endpoints. Required values must be filled before you can continue.
5. Select **Install extension**. The extension starts with the values you entered.

An extension with no server to configure installs as soon as you select **Configure extension**.

Extensions you've already installed stay in the list with an **Already installed** tag, and can't be selected again.

## Install a package from a file

Install from a file when you have a package of your own. It becomes a **Local** package that only your workspace sees.

1. Go to **Settings** → **Extensions**.
2. Select **Add private extension** and choose the file, or drag the package onto the page. While you drag, the page shows *"Drop to install an extension"*.

You can also drop a package onto the list inside the **Install** dialog. The package is added and selected for you, ready to configure and install.

Dropping a file in any other format shows a warning and uploads nothing. To change a package's contents, give it a new version number: installing the same version again reuses the release already installed.

## Edit an installed extension's files

Selecting **Enable development mode** on an installed extension lets someone edit its files. Updates to that extension pause until development mode is turned off.

## Configure an extension so it starts running

A package you install from a file is installed without any configuration. If it needs values, it stays installed but not running, and its card shows **Configuration needed**, so you can install it now and configure it when you have the credentials. Saving the first configuration starts the extension and lists its tools.

1. Open the extension on **Settings** → **Extensions**.
2. Open **Settings** from its options menu and fill in what the extension asks for: API keys, connection strings, endpoints.
3. Save. The extension comes up enabled, and its tools appear.

An extension whose parameters all have defaults starts as soon as you install it.

If a required value is missing, the save is refused and the extension stays disabled until you correct it and save again.

An extension can hold **more than one** configuration of the same server (a second set of credentials, a second endpoint), and each discovers its own tools. The first configuration is the default one and can't be deleted while the extension is installed; deleting any of the extras leaves the extension enabled on the default.

## Pick a connector instead of typing a credential

Some extensions don't ask you to paste an API key. Their manifest asks for a **connector** of a given type instead: a credential you already saved once in **Settings** → **Connectors** (see [Configure connectors](/operational-guides/configure-connectors)). One connector can serve several extensions, and you rotate the key in one place.

1. Create the connector in **Settings** → **Connectors**, if you haven't already.
2. Open the extension's configuration on **Settings** → **Extensions**. Each connector parameter is a drop-down that lists only the connectors of the type the extension needs.
3. Select the connector and save.

You make the same choice when you add or edit an MCP server configuration from a touchpoint's **Tools** tab: the connector field opens a searchable list. If it shows *"No connectors available"*, no connector of the required type exists yet; create one in **Settings** → **Connectors** and open the dialog again.

Extensions that call Rational AI itself, such as [Marketplace](/operational-guides/marketplace) solutions, get the built-in Rational AI connector filled in for them.

## Configure remote (HTTP) MCP servers

Some MCP servers run inside Rational AI (**Local**), others are reached over the network (**Remote**), and one extension can have both. A remote server needs its endpoint URL and, usually, an authentication value.

### Tell local and remote servers apart

Open the extension's **details** page and find the **MCP servers** section. A remote server shows a **Remote** chip and its endpoint URL; a local one shows a **Local** chip. The same view lists the tools the extension provides.

### Add authentication for a remote server

For a remote server that requires authentication, enter the token in the extension's configuration form. The token is stored in your configuration, not in the package.

:::note[Ready-made remote extensions]
The catalog includes remote extensions for services such as GitHub, Linear, Atlassian, Snowflake and Sentry. Each needs only an endpoint URL and an authentication value. To connect any other remote MCP server, use the generic **remote-mcp** extension.
:::

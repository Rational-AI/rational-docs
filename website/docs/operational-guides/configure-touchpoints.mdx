# Configure touchpoints

A touchpoint is an assistant that answers people in conversations. It holds the system prompt, the models, the knowledge the assistant reads, the tools and skills it can use, and its memory. A [channel](/operational-guides/manage-channels) only carries the messages: the Chat, a Telegram bot, a mailbox, an API. Touchpoints are separate from the agents of [Agents](/cr/Agents).

Some touchpoints are created for you: creating a [Knowledge](/operational-guides/create-knowledge) also creates the Knowledge's touchpoint, and the **Default touchpoint** is the workspace assistant behind the [Chat](/cr/Chats).

## Prerequisites

- **Permission to manage touchpoints:** a role with **Update** on **Touchpoints**, plus **Create** to add one (see [Roles and users](/operational-guides/roles-and-users)). Adding, editing or removing a touchpoint's tools, and marking them **Sensitive**, needs the administrator role.
- **At least one [channel](/operational-guides/manage-channels)** to create a touchpoint. **New** is unavailable while no channel exists.

## Create a touchpoint

1. Go to **Settings** → **Touchpoints** and select **New**. With no touchpoints yet, the button is **Add new**.
   Rational AI creates an enabled touchpoint named *New touchpoint* on your first channel and opens it.
2. Replace the name at the top of the panel, and optionally enter a description.
3. On the **Settings** tab, select the **Channel** people will reach the assistant through.
4. On the **Models** tab, write the **System prompt** and check the models. A new touchpoint starts with your platform's default **Conversational model**, set under **Settings** → **AI Model Registry**.
5. On the **Sources** tab, add the knowledge the assistant should read.
6. Select **Save**.

To start from an existing touchpoint instead, open it and select **Duplicate** in its menu.

## Find your way around a touchpoint

Go to **Settings** → **Touchpoints** and select the touchpoint you want to configure. It opens on its **Settings** tab.

A touchpoint's settings are spread over seven tabs:

| Tab | What you set there |
|-----|--------------------|
| **Settings** | Channel, **Allow anonymous access**, the chat features users get (**Canvas mode**, **Edit messages**, **Attachments**, **Regenerate response**) and, on API touchpoints, the [API key](/operational-guides/api-access#give-an-application-its-own-touchpoint-key) |
| **Models** | System prompt, models, [reasoning, generation limits and response verification](/operational-guides/touchpoint-generation), title, sentiment and topic generation, and suggested questions |
| **Sources** | The knowledge the assistant reads, and whether it [may change it](#let-the-assistant-change-a-knowledge) |
| **Tools** | The tools the assistant may call, when they need confirmation, and how long they may take |
| **Skills** | The [skills](/operational-guides/agent-skills) the assistant can use |
| **Memory** | [Memory and long conversations](/operational-guides/touchpoint-memory) |
| **Test runs** | [Replays of past conversations](/operational-guides/test-touchpoint-changes) against a change |

Select **Save** at the bottom of the panel to keep your changes, or **Undo** to discard them. Without **Update** on **Touchpoints**, the form is read-only and has no **Save**.

## Edit the system prompt

The **System prompt**, at the top of the **Models** tab, is the standing instruction the assistant follows on this touchpoint. Two buttons sit beside the field:

- **Show unsaved changes** switches the field into a read-only diff view, comparing what's saved against what you've typed. It's disabled while nothing has changed.
- **Expand editor** gives the prompt a much taller editing area and hides the other fields of the tab while you work.

:::note[Test a prompt change before it goes live]
When you change the prompt or models of a touchpoint with at least five past conversations to replay, **Save** offers to replay your change against them first, so you can see what came out different before your users do. See [Test a touchpoint change](/operational-guides/test-touchpoint-changes).
:::

### Change the workspace assistant's prompt

The assistant people talk to in the main [Chat](/cr/Chats) is a touchpoint too: the **default touchpoint**, named *Rational AI*. You can rewrite its instructions like any other, for example to give it your company's tone or rules.

1. Go to **Settings** → **Touchpoints** and select **Default touchpoint** at the top of the list. It opens on the **Models** tab.
2. Edit the **System prompt** and save. Changes apply from the next message, in existing chats as well as new ones.
3. To go back to Rational AI's own instructions, select **Restore default**, then **Save**.

:::note[The prompt is yours; permissions and tools are not]
Rewriting the prompt changes how the assistant talks and what it focuses on. Which knowledge each person can reach and which tools are available stay managed by Rational AI: on the default touchpoint every user automatically gets all enabled knowledge they are allowed to read. An empty prompt falls back to the built-in default. The default touchpoint can't be deleted.
:::

## Control who can reach the touchpoint

Use this to decide whether someone must sign in before they can talk to the assistant. By default they must.

1. On the **Settings** tab, find **Allow anonymous access**.
2. Turn it on to let people start a conversation without signing in, or leave it off to require sign-in.
3. Save the touchpoint.

Turn it on only for a touchpoint meant for the public, such as a help assistant on your website.

## Let the assistant change a knowledge

By default an assistant only reads the knowledge attached to it. For an assistant whose job is to keep records up to date (logging a request, updating a customer, filing a document), you can let it write as well, one knowledge at a time.

1. Open the touchpoint's **Sources** tab.
2. On the knowledge you want the assistant to maintain, turn on **Can change records**.
3. Read the confirmation and select **Allow changes**.

The change applies at once, without the touchpoint's **Save**. The assistant can then create and update records, move them between collections and create collections in that knowledge, but never delete anything. Each change it makes shows the assistant's name, and people working in the knowledge are told when records have been changed so they can reload. Turn **Can change records** off to take the right back; no confirmation is needed.

:::warning[Anyone who can use the assistant can ask for changes]
The permission belongs to the assistant, not to the person chatting. Everyone who can reach the touchpoint can ask it to change records: people in the chat, applications calling its [API or MCP endpoint](/operational-guides/api-access) and, on a public touchpoint, anonymous visitors. Only someone who can edit the knowledge can turn this on, and it is off by default.
:::

The default touchpoint has no such switch: there, the assistant changes records only within the permissions of the person chatting.

## Choose the tools the assistant can use

Tools let the assistant act beyond answering from its knowledge, for example searching a Knowledge or querying a database. They come from installed [extensions](/operational-guides/manage-extensions), and a touchpoint needs none.

1. Open the touchpoint's **Tools** tab.
2. Open **Add tool...** and select a tool. Tools are grouped by the extension that provides them.
3. In the **Add tool** dialog, optionally change the **Alias** and **Description** the assistant sees.
4. For each parameter, choose who sets it: **Auto** lets the assistant decide while it answers, **Manual** fixes a value you enter, and **Default** keeps the extension's value. A parameter that names a Knowledge shows a list of Knowledges to pick from.
5. Select **Confirm**, then **Save** the touchpoint.

To change or take away a tool, use **Edit tool** or **Remove tool** in its menu.

## Decide when a tool needs confirmation

At the top of the **Tools** tab, **When to ask for confirmation** sets which tool calls a person must approve first.

1. Open the **When to ask for confirmation** dropdown.
2. Choose the policy for this touchpoint:
   - **Never: tools run without asking**
   - **Smart: only for sensitive tools (recommended)**. The default: read-only tools run straight through, sensitive ones wait.
   - **Always: ask before every tool**
3. Save the touchpoint.

Under **Smart**, each tool row has a **Sensitive** badge. Select it to mark the tool sensitive or not on this touchpoint; the change applies at once. Until you do, the tool follows what its extension declares.

When a call needs approval, the chat pauses on an approval card until the user approves it (see [Approve tool calls](/operational-guides/approve-tool-calls)). A touchpoint registered as a high-risk application in [Governance](/operational-guides/governance) asks before every tool call, whatever policy you choose.

## Set how long a tool may take

When a tool call runs out of time, the assistant is told the call failed and carries on.

1. In the **Tools** tab, find **How long a tool may take**.
2. Enter a limit in seconds, or leave it empty for the default of 120 seconds. The maximum is 600.
3. Save the touchpoint.

If a tool runs out of time on every attempt, the answer stops with *"Generation stopped: the tool "…" ran out of time on every attempt."* and a **Regenerate response** button. Raise the limit, or find out why the tool is slow.

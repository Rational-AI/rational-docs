# Configure touchpoints

A touchpoint is the bridge between one of your [Knowledges](/operational-guides/create-knowledge) and the people (or systems) asking it questions. It decides two things: who is allowed to reach the agent, and which tools the agent may use when it answers. This guide walks through the touchpoint configuration panel and the **Tools** tab.

<Admonition type="info" icon="📖" title="WHAT IS A TOUCHPOINT?">
A touchpoint connects a Knowledge to the outside world. It carries the access settings for the agent and the set of tools the agent is allowed to use when answering. Those tools come from your installed MCP servers — MCP (Model Context Protocol) is the standard Rational uses to let an AI agent call out to external capabilities like search or database queries. When you create a Knowledge, Rational also creates a default touchpoint for it, which you then refine here.
</Admonition>

## Prerequisites

Before you start, make sure you have:

- **Administrative access:** an account with touchpoint management privileges.
- **A touchpoint to configure:** for example the default touchpoint created with your Knowledge.
- **At least one MCP extension installed:** a touchpoint can only offer tools that an installed MCP server exposes (for example the `rational-knowledge-rag` extension). See [Manage extensions](/operational-guides/manage-extensions) if you need to install one.

## Open a touchpoint

Go to **Settings** → **Touchpoints** and select the touchpoint you want to configure. This opens the configuration panel, where access settings live, alongside the **Tools** tab.

## Control who can reach the touchpoint

Use this to decide whether someone must sign in before they can talk to the agent. By default they must.

<img
  src={require('@site/static/img/screens/touchpoint-anonymous.png').default}
  alt="The Allow anonymous access toggle on a touchpoint"
  style={{ width: '100%', maxHeight: '100%', objectFit: 'contain', border: '1px solid #E4E4E7', borderRadius: '6px', boxSizing: 'border-box' }}

*The Allow anonymous access toggle in the touchpoint configuration panel.*

1. In the configuration panel, find the **Allow anonymous access** toggle.
2. Turn it **on** to let anyone reach the touchpoint without authenticating, or leave it **off** to require sign-in.
3. Save the touchpoint to apply the change.

<Admonition type="note" icon="📝" title="OFF BY DEFAULT">
Only enable **Allow anonymous access** when the touchpoint is genuinely meant to be reached without sign-in, such as a public help assistant. Once saved, the setting persists with the touchpoint.
</Admonition>

## Work with tools

The **Tools** tab is where you choose exactly which capabilities the agent can call. Open it to see your tools organized in a nested view rather than as a flat table:

- One **card per MCP server**.
- Under each server, a **`CONFIGURATION`** list. A configuration is a named, reusable set of settings (parameters and sources) for that server.
- Each configuration expands to show the tools added under it, listed as **alias · tool name · description**.

A configuration that has no tools yet is marked with an **`Unused`** chip, so you can spot at a glance where nothing has been wired up.

### Reading the two dropdowns

Two pickers drive everything in this tab. Both render as grouped, styled lists so you can see where each option comes from.

- **Add tool…** shows a **group header per MCP server** (with the extension's icon) and the tool rows indented beneath it. For example, the `rational-knowledge-rag` extension appears under a **RAG MCP server** group with its tools listed below: `rag_query_simple`, `get_resource`, `get_user_context`, `get_schema`, `execute_query`, `list_databases`, and `rag_query_graph`.
- **Add MCP server configuration…** offers **+ Add new configuration** at the top and then lists the available configurations, each shown with the server icon and an expand chevron.

## Add a single tool

Reach for this when you want one specific capability with parameters tuned exactly how you like.

1. In the **Tools** tab, open the **Add tool…** dropdown and select a tool from its MCP server group.
2. In the **Add tool** dialog, set each parameter's mode using its **Default / Auto / Manual** dropdown. **Default** inherits the configuration's value, **Auto** lets the agent decide at answer time, and **Manual** lets you fix the value yourself.
3. To undo a change to any parameter, use the **revert-to-default** button next to its mode dropdown. The button disables itself once the parameter is back in default mode.
4. Select **Confirm**.

<Admonition type="note" icon="📝" title="SINGLE-CONFIGURATION SHORTCUT">
When the server has only one configuration, the configuration dropdown is hidden in the **Add tool** dialog — there is nothing to choose between.
</Admonition>

## Bulk-add a configuration's tools

When you trust a configuration's defaults and just want everything it offers, add all of its tools in one action instead of picking them one by one. There are two entry points:

- **Pick a configuration** in the **Add MCP server configuration…** picker to add all of its tools at once.
- Use the **Add all tools** action on a configuration row, found in its `⋮` menu.

Each tool is created with no parameter overrides, so it inherits the configuration and tool defaults. Any required field that has no default falls back to LLM **Auto** — exactly as if you had added the tool individually and left its defaults untouched.

When the bulk-add finishes, a toast confirms the result, for example **Added 2 tools**.

<Admonition type="note" icon="📝" title="WHAT GETS SKIPPED">
Tools already present are skipped (deduplicated by tool id). If a configuration is empty or already fully added, nothing is created and you get an info toast instead. Partial failures report counts without losing the tools that succeeded.
</Admonition>

## Add a new MCP server configuration

Create a configuration when you want a named, reusable set of settings for a server — for example one configuration pointed at a specific data source, ready to drop tools into.

1. In the configuration picker, select **+ Add new configuration**.
2. In the **New MCP server configuration** dialog, choose the **server** from the dropdown.
3. Enter the **configuration name** in the top-level name field.
4. Fill in the collapsible **Params** and **Sources** sections. Sources resolve from the selected server, so they are available while you create a configuration, not only when editing one later.

## Point a tool at a specific Knowledge

Some tools take a knowledge-reference parameter (`knowledgeId` / `knowledge_id`) to say which Knowledge they should act against. Rather than asking you to paste a raw ID, this parameter renders as a **searchable knowledge dropdown**.

1. In the **Add tool** dialog, find the knowledge-id parameter.
2. Set its mode to **Manual** to override it, or leave it on **Auto** / **Default** to let the agent resolve it.
3. Open the dropdown and **filter by name** to find the Knowledge you want. The touchpoint's knowledges are shown by **name** and resolved to their **id** behind the scenes.

<Admonition type="note" icon="📝" title="NO MORE RAW IDS">
Because knowledge IDs are never surfaced in the UI, this dropdown is the supported way to pick a Knowledge for a manual override — there is no need to type an ID by hand. The same auto/manual/default modes and validation as the other tool-parameter controls apply.
</Admonition>

## Result

Your touchpoint now controls its own access through the **Allow anonymous access** toggle, presents a nested **Tools** view grouped by MCP server and configuration, and lets you add tools either one at a time or in bulk with defaults inherited. Knowledge-id parameters are filled from a searchable dropdown instead of raw IDs — so the agent has exactly the tools and references it needs to answer against your Knowledge.

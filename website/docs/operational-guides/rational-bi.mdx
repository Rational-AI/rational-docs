# Build BI dashboards

**BI** turns the data already in Rational AI into dashboards you can filter, share and export, and into written reports. Work is organized in **projects**: each one holds a set of dashboards and reports on the same data, so sales reporting can stay apart from operations reporting.

This guide starts with what everyone does in a project (build, filter and export dashboards), then covers how builders set up a project and how administrators control who sees what.

## Open BI

Select **BI** in the top navigation. It appears only when your [license](/operational-guides/license) includes Rational BI. The first page lists your projects; open one to see its **Dashboards** and **Reports**.

The first time you open BI, a guided tour walks you through projects, dashboards, the chat and reports. Replay it at any time with the **Guide** button.

## Build a dashboard

Inside a project, select **New dashboard** (or the **+** next to **Recents** in the sidebar). The dialog asks *"How would you like to get started?"*:

- **Generate with AI**: describe the dashboard and Rational AI builds the charts, metrics and layout. This is the usual way to start.
- **Build manually**: start from an empty canvas, ask the AI chat for one chart at a time and arrange them yourself.

### Generate it with AI

1. Select **Generate with AI**, then **Next**.
2. Describe the dashboard in plain language: what it should track, which trends and comparisons to show, and how to lay it out. The box starts from the project's own instructions when it has some.
3. Select **Generate**. The new dashboard opens, named after your description, and shows *"Rational AI is building your dashboard…"* while the charts appear.
4. If Rational AI needs more information, it says so on the canvas. Reply in **Chat** to let it continue. If generation fails, select **Retry**.

Charts are saved as they are produced, so leaving the page mid-generation loses nothing. If a chart ends up in the chat without reaching the canvas, a banner offers **Add all** to place it and **Dismiss** to ignore it.

Once the dashboard exists, open **Chat** on it whenever you want to add or change charts. The chat can also chart the **records** of a Knowledge, for example *"open deals by stage from the CRM"*. Record-based widgets are computed with each viewer's own access, so two people can see different numbers on the same dashboard. They ignore the dashboard's filter bar and show no rows inside a report.

Charts write numbers and dates in your interface language: in Italian, *25,000.8* becomes *25.000,8*.

### Lay it out by hand

Select **Actions** → **Edit** to rearrange a dashboard. Drag widgets around the grid, resize them from the corner grip, and add blocks from the settings sidebar's **Sections** tab:

- **Title**: a heading, **Heading 1** to **Heading 4**.
- **Free text**: a paragraph of explanation next to the numbers.
- **KPI card**: one headline number with its label, backed by a query.
- **Graphs**: a chart.
- **Tables**: the data behind one of the dashboard's charts, shown as a table.
- **Divider** and **Spacer**: a horizontal rule and empty space between blocks.

The sidebar's **Settings** tab holds what applies to the whole dashboard, including **Global colors** and **Delete dashboard**. Select **Save** to keep your changes, or **Cancel** to drop them.

**Auto layout**, in the **Actions** menu, moves every widget up as far as it fits to close the gaps, and saves the result.

### Tune a single chart

Select a chart to open **Chart settings** in the sidebar:

- **Chart type**: bar, line, area, scatter, pie, donut, radar, or **Geographic map**.
- **Data source**, **SQL Query** and **Available tables**: what the chart queries.
- **Colors** and **Legend position**.
- **Advanced (Spec)**: the underlying chart specification, for what the controls don't expose.
- **Remove chart**: take this widget off the dashboard.

A **Geographic map** colors each region by its value. Two maps are available: **US states** and **Italian regions**. Rational AI picks the map whose region names match the chart's categories, so a column of US state names or Italian region names is all it needs. You can also ask for one in the chat, for example *"sales by region on a map of Italy"*.

## Filter a dashboard

Select **Filters** on a dashboard to open its filter panel. Each filter is a list of values to pick from, or a date range. Pick values and select **Apply**; the charts and KPI cards that use the filter re-run their queries. **Clear** removes your selection.

- To generate filter suggestions from the dashboard's data, select **Refresh filters**.
- To add one yourself, select **Add filter**, choose a **Table** and a **Column**, and optionally a column to **Show this instead of the value** (for example a name instead of an ID, taken from a **Lookup table**). Then select **Add**.
- A filter used in the widgets' queries but not linked to a column filters nothing. **Add filter** then offers **Unlinked filter**: pick the filter and the column it should use.

## Keep a dashboard up to date

A saved dashboard shows the data captured when its charts were generated. To keep an open dashboard current, select **Actions** → **Auto-refresh** and choose **Off** (the default), **30 seconds**, **1 minute**, **5 minutes** or **15 minutes**.

While the dashboard is open, Rational AI re-runs each widget's saved query on that interval. No model is involved, so the chart stays the same and only the numbers change. If a refresh fails, the dashboard keeps showing the last good data.

**Edit**, **Auto-refresh** and **Auto layout** appear only when your role has **Update** on **Dashboards**, and **Delete** only with **Delete** on **Dashboards**.

## Export a dashboard

Open the dashboard and select **Actions** → **Download**, then pick a format:

| Format | What you get |
|---|---|
| **PDF** | A picture of the dashboard as it looks on screen. |
| **CSV** | One file with a block per chart and KPI card, in grid order. Each block opens with a `#` line carrying the widget's title. Titles, text, dividers and spacers are left out. |
| **Tableau** | A packaged Tableau workbook (`.twbx`) with native, editable charts and their data. |

**Tableau** opens **Export to Tableau**, listing every dashboard in the project with the current one already selected. Select the others you want, or **Select all**, then **Download**. Each dashboard becomes a Tableau dashboard in the same workbook, and its filters become Tableau filter controls set to your current selection. Widgets built on tables you can't see are left out.

**Download** is unavailable while the dashboard is still being generated, and **PDF** and **Tableau** need at least one widget.

## Pin the dashboards you use most

In the BI sidebar, open a dashboard's or report's menu and select **Pin**. Pinned items get their own **Pinned** section above **Recents**; drag them to reorder, and select **Unpin** to take one off. The sidebar shows ten pins, with **More** for the rest. Pins are stored in your browser, so they don't follow you to another computer.

## Write a report from your dashboards

A report is a written summary of what one or more dashboards show.

1. In the project sidebar, select **+** next to **Reports**. The **Generate report with AI** dialog opens.
2. In **Reference dashboard(s)**, select one or more dashboards. Edit the **Prompt** to say what the report should cover.
3. Select **Generate with AI**, or **Create manually** to lay the report out yourself.
4. The report opens as a draft. Review it and select **Create** to save it.
5. Use the report's **Chat** to change it: a different emphasis, a shorter summary, an added section. In **Edit** mode, the **Report settings** sidebar adds graphs and tables from the linked dashboards, dividers, images and web components. KPI cards aren't supported in reports.

The report's **Actions** menu holds **Refresh data** (re-runs the queries behind its graphs and tables), **Duplicate**, **Auto layout**, **Download** (**PDF**, **CSV** or **Excel**) and **Delete**.

A dashboard can also appear inside a Knowledge, next to the documents, as a [custom view](/operational-guides/knowledge-custom-views).

## Set up a project

Projects are created and configured in **Settings** → **Rational BI**. Creating one needs **Create** on the **BI projects** row of your role.

### Create a project

1. In **BI**, select **New**. This opens **Settings** → **Rational BI**.
2. Select **New** → **From scratch**. Rational AI creates a project called *New project* and opens its configuration.
3. Enter a name that describes its dashboards, for example `Sales Reporting`, add a description, and select **Save**.

The project's tabs are **Settings** (name and description), **Sources**, **Models** (the models and instructions used to generate charts and reports), **Tools** (what its assistant can call) and, for administrators, **Access**.

### Give the project something to query

A dashboard can only chart data the project can reach.

1. Open the project's **Sources** tab. It lists everything the project can query, whether it came from a [data source](/operational-guides/configure-sources) or a [Knowledge](/operational-guides/create-knowledge), with its **Name**, **Description** and number of **Files**.
2. Use the **Add...** field to attach another source or Knowledge, and the row's **⋮** menu to **Remove** one. Each change is saved straight away.

### Offer suggested questions

The project's **Models** tab has a **Suggested questions** section. Its questions appear as chips when someone opens a dashboard's **Chat**.

1. Select **Generate with AI**. Rational AI uses the project's **Default model** to write five questions from the project's description, instructions and sources.
2. Remove the ones you don't want with **✕**, and type your own into the field under the list.
3. Make sure **Enable example questions?** is on, then select **Save**.

**Generate with AI** replaces the questions already in the list, but nothing is stored until you **Save**.

### Switch a project off or move it

On **Settings** → **Rational BI** → **Projects**, every project card has an enable switch (it needs **Update** on **BI projects**). Turned off, the project disappears from **BI** for everyone and keeps its configuration, so you can park a project you are still preparing.

To copy a project to another workspace, open it, open the menu next to its name and select **Export (JSON)**. In the other workspace, select **New** → **Import JSON** and choose the file. The import creates a new project with the file's dashboards and reports. If they refer to Knowledges that don't exist there, a message lists them, and their widgets don't load until you point the project at the right sources.

## Control who sees the data

By default, everyone who can open a project can query all of its data. Administrators can narrow it on the project's **Access** tab, and set the defaults for new projects. Administrators always see everything.

### Choose who sees each table and view

1. In **Settings** → **Rational BI**, open the project and select the **Access** tab. It lists every **Table or view** of the project's Knowledges, with **Who can see** next to each.
2. Select a row and choose **Everyone in this project** (the default), **Nobody**, or **Selected groups and roles** and search for the [groups and roles](/operational-guides/roles-and-users).
3. Select **Save**.

The rule applies to dashboards, reports and the project's chat. A chart built on data someone can't see tells them *"You don't have access to this chart's data"*. A view is judged on its own: you can publish an aggregated view to everyone while the table underneath stays restricted, and a hidden table looks to others as if it didn't exist.

### Filter rows and mask columns

For the tables and views of a database tagged **Virtual** in its Knowledge, select **Rows and columns** on the row:

- **Row filter**: a SQL condition on the view's columns. A placeholder such as `{{user.email}}` or `{{user.groups}}` makes each viewer see only their own rows, for example `email = {{user.email}}`.
- **Column masks**: set a column to **Partial** (keeps the first and last character of a text) or **Hidden** (returns no value). Columns left **Visible** are shown as they are.

Select **Save**. The row then shows **Filtered** or the number of masked columns. A view whose **Who can see** is **Nobody** has nothing to filter.

### Set the defaults for new projects

**Settings** → **Rational BI** → **BI defaults** holds the workspace-wide BI settings, and needs **Update** on the **BI defaults** row of your role. The model and tools are copied into new projects only.

| Setting | What it does |
|---|---|
| **Chat model** | The model for chats in new projects. Use a coding model: chart generation and data queries rely on tool calling. |
| **Model template prompt** | The core instructions for the assistant when it analyzes data or generates dashboards. |
| **Report starter prompt** | The instructions Rational AI follows for every report, in every project. The report's **Prompt** is added to them. |
| **Default tools** | The tools available in new projects. The semantic search tools need the project's Knowledge to have an embedding model. |

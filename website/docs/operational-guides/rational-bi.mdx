# Build BI dashboards

Rational BI is where you turn your data into business-intelligence dashboards: visual, shareable views that surface trends and answer questions at a glance. This guide takes you from an empty project to a dashboard that builds itself from a conversation, keeps its own data fresh, and can be laid out exactly how you want it.

:::note[What is Rational BI?]
Rational BI is a dedicated area for building business-intelligence (BI) dashboards on top of the data already in Rational AI. Your work is organized into **projects** — a project is the central workspace that holds a related set of dashboards, so you can keep, say, your sales reporting separate from your operations reporting. A project also holds **reports**: written summaries generated from one or more of its dashboards.
:::

## Open Rational BI

Select the **BI** tab in the top navigation. (You can also reach it from **Settings** → **Rational BI**.)

The first thing you see is your list of projects. If you haven't created any yet, this is an empty state inviting you to make your first one.

The first time you open BI, a two-minute guided tour walks you through projects, dashboards, the chat and reports. Skip it if you like; you can replay it at any time with the **Guide** button.

*The **BI** area: your projects. Each project is the workspace for a set of dashboards.*

## Create a project

Everything in Rational BI lives inside a project, so the first step is to create one.

1. From the **BI** area, select **New**.
2. Give the project a clear **name** — something that describes the dashboards it will hold, for example `Sales Reporting`.

Your new project appears in the list and opens as a workspace ready for you to start building.

:::note[Group dashboards by purpose]
Use a separate project for each distinct reporting area or audience. Keeping related dashboards together makes them easier to find and to manage as your reporting grows.
:::

## Give the project something to query

A dashboard can only chart data the project can reach, so point the project at its sources before you start building.

1. Go to **Settings** → **Rational BI** and open the project.
2. Open its **Sources** tab. Everything the project can query is listed in a single table, whether it came from a [data source](/operational-guides/configure-sources) or from a [Knowledge](/operational-guides/create-knowledge):
   - **Name**, with the provider's own icon, so you can tell a cloud-storage source from a Knowledge at a glance.
   - **Description**.
   - **Files** — how many files that entry contributes.
3. Use the **Add…** field below the table to attach another source or Knowledge; use the row's **⋮** menu to **Delete** one.
4. Select **Save**.

The neighbouring tabs cover the rest of the project: **Settings** for its name and description, **Models** for the models and instructions it uses when generating charts and reports, and **Tools** for what its assistant can call. Administrators also see an **Access** tab, covered below.

### Switch a project off

On **Settings** → **Rational BI** → **Projects**, every project card has an enable switch. Turn it off and the project disappears from the **BI** area for everyone, while its configuration stays intact in **Settings** — a way to park a project you are still preparing, or retire one without deleting it. Turning the switch back on restores it as it was.

### Choose who sees each table and view

By default, everyone who can open a project can query all of its data. When some of it is sensitive (salaries next to headcount, margins next to revenue), narrow it table by table.

1. In **Settings** → **Rational BI**, open the project and select the **Access** tab.
2. The table lists every **Table or view** of the project's Knowledges, grouped by Knowledge, with **Who can see** next to each.
3. Select a row and choose:
   - **Everyone in this project** — the default.
   - **Nobody**.
   - **Selected groups and roles** — search for the [groups and roles](/operational-guides/roles-and-users) that should see it.
4. Select **Save**.

The rule applies everywhere the project's data is read: dashboards, reports and the project's AI chat. A chart built on data someone can't see tells them *"You don't have access to this chart's data"* instead of showing numbers. Administrators always see everything.

:::note[A view is judged on its own]
Granting a view does not expose the table underneath it. That lets you publish an aggregated view (totals by department, say) to everyone, while the table with individual rows stays restricted. To the people who can't see it, a hidden table looks exactly like one that doesn't exist, so even the AI chat can't reveal its name.
:::

### Offer suggested questions

An empty chat is hard to start. The project's **Models** tab has a **Suggested questions** section whose questions appear as clickable chips when someone opens the dashboard **Chat**.

1. In the project's **Models** tab, find **Suggested questions**.
2. Select **Generate with AI**. Rational AI uses the project's **Default model** to write five questions from the project's description and instructions and from the names and descriptions of its Knowledges and sources, in the language they are written in.
3. Remove the ones you don't want with **✕**, and type your own into the field below the list.
4. Make sure **Enable example questions?** is on, then select **Save**.

:::note[Generating replaces the list]
**Generate with AI** replaces the questions already in the list, and nothing is stored until you **Save** — so if you don't like the result, leave without saving and your previous questions are still there. Generation needs a **Default model** on the project.
:::

## Build a dashboard

Inside a project, **Dashboards** holds your dashboards and **Reports** holds the written summaries. Select **New dashboard** (or the **+** next to **Recents** in the sidebar) to start one. The dialog asks *"How would you like to get started?"*:

- **Generate with AI**: describe the dashboard and Rational AI builds the charts, metrics and layout for you. This is the usual way to start.
- **Build manually**: start from an empty canvas, ask the AI chat for one chart at a time and arrange them yourself.

### Generate it with AI

1. Select **Generate with AI**, then **Next**.
2. Describe the dashboard you want in plain language: what it should track, which trends and comparisons to show, and how to lay it out. The box starts from your project's own instructions when it has some.
3. Select **Generate**. The new dashboard opens, named after your description, and the canvas shows *"Rational AI is building your dashboard…"* while the charts appear.
4. If Rational AI needs more information, it says so on the canvas. Reply in **Chat** to let it continue. If generation fails, select **Retry**.

Once the dashboard exists, open **Chat** on it whenever you want to add or change charts.

The chat can also chart the **records** of a Knowledge (a collection with its filters, groupings and summaries) rather than a SQL query: ask for it, for example *"open deals by stage from the CRM"*. Record-based widgets are computed for each viewer with that viewer's own access, so two people can see different numbers on the same dashboard. They take one collection each, aren't affected by the dashboard's filter bar, and show no rows inside a report.

:::note[Numbers follow your language]
Charts write numbers and dates the way your interface language does: switch to Italian and *25,000.8* becomes *25.000,8* and months read *gen, feb*. KPI cards built on records are formatted the same way. KPI cards built on a SQL query keep the format they were given when they were last refreshed.
:::

:::note[Charts survive leaving the page]
Generated charts are saved to the dashboard as they are produced, so navigating away or reloading mid-generation does not lose them. If any chart does end up in the chat without reaching the canvas, a banner on the dashboard says how many are outstanding, with **Add all** to place them and **Dismiss** to ignore them.
:::

### Lay it out by hand

Select **Actions** → **Edit** to rearrange a dashboard. In edit mode you can drag widgets around the grid, resize them from the corner grip, and add structure from the settings sidebar's **Sections** tab:

- **Title** — a heading, at level **Heading 1** to **Heading 4**, so a long dashboard reads as sections rather than a wall of charts.
- **Free text** — a paragraph of explanation next to the numbers.
- **KPI card** — one headline number with its label. It is backed by a query, so it refreshes like a chart.
- **Graphs** — a chart.
- **Tables** — the data behind one of the dashboard's charts, shown as a table. Pick the chart from the list.
- **Divider** — a horizontal rule.
- **Spacer** — empty space between blocks. In edit mode, set its minimum height in pixels.

The sidebar's **Settings** tab holds what applies to the whole dashboard, including **Global colors** and **Delete dashboard**. Select **Save** to keep your changes, or **Cancel** to drop them.

### Tune a single chart

Select a chart to open **Chart settings** in the sidebar:

- **Chart type** — bar, line, area, scatter, pie, donut, radar, or **Geographic map**.
- **Data source**, **SQL Query** and **Available tables** — what the chart queries.
- **Colors** and **Legend position**.
- **Advanced (Spec)** — the underlying chart specification, when you want to hand-tune something the controls don't expose.
- **Remove chart** — take this widget off the dashboard.

:::note[Geographic maps]
A **Geographic map** colors each region by its value. Two maps are available today: **US states** and **Italian regions**. You don't upload any map files: Rational AI looks at the chart's categories and picks the map whose names they match, so a column of US state names or Italian region names is all it needs. Capitalisation and extra spaces don't matter. You can also ask for a map in the chat, for example *"sales by region on a map of Italy"*.
:::

## Keep a dashboard up to date

A saved dashboard shows the data captured when its charts were generated. To keep an open dashboard current, give it a refresh interval.

1. Open the dashboard and select **Actions** → **Auto-refresh**. The menu item shows the current setting.
2. Choose an interval:
   - **Off — refresh manually** (the default).
   - **Every 30 seconds**
   - **Every minute**
   - **Every 5 minutes**
   - **Every 15 minutes**

While the dashboard is open, Rational AI re-runs each widget's saved query on that interval and patches the results in place.

:::note[Refreshing is not regenerating]
Auto-refresh re-runs the query the chart already has. No model is involved, so it is deterministic and cheap: the same chart, newer numbers. Asking the AI for a *different* chart is a separate, deliberate action in the chat. Background refreshes are also silent — if one fails, the dashboard keeps showing the last good data rather than interrupting whoever is looking at it.
:::

The rest of the **Actions** menu holds **Edit**, **Auto layout**, **Download** and **Delete**.

**Auto layout** tidies the grid: it moves every widget up as far as it fits, closing the empty gaps left after moving or removing widgets, and saves the result. Widget sizes stay the same.

## Export a dashboard

To take a dashboard out of Rational AI, open it and select **Actions** → **Download**, then pick a format:

| Format | What you get |
|---|---|
| **PDF** | A picture of the dashboard as it looks on screen, in a file named after it. |
| **CSV** | One file with a block per chart and KPI card, in the order they sit on the grid. Each block opens with a `#` line carrying the widget's title, followed by its data. Titles, text, dividers and spacers are left out. |
| **Tableau** | A packaged Tableau workbook (`.twbx`) with native, editable charts and their data included. |

**Tableau** opens an **Export to Tableau** dialog listing every dashboard in the project, with the current one already ticked. Tick the others you want, or **Select all**, then select **Download**: each dashboard becomes a Tableau dashboard in the same workbook. The dashboard's filters come along as native Tableau filter controls, set to your current selection, so they keep working once the file is opened in Tableau.

:::note[An export only contains what you can see]
Widgets built on tables you don't have access to are left out of the workbook. If interactive filters can't be built for a dashboard, it is exported with its current values and its charts stay editable; Rational AI tells you when that happens.
:::

**Download** is unavailable while the dashboard is still being generated, and **PDF** and **Tableau** need at least one widget on it.

## Pin the dashboards you use most

In the BI sidebar, open a dashboard's or report's menu and select **Pin**. Pinned items get their own **Pinned** section above **Recents**; drag them up and down to put them in the order you want, and select **Unpin** to take one off. The sidebar shows ten pins, with **More** for the rest.

:::note[Pins belong to this browser]
Pins and their order are stored in your browser, not in your account. They don't follow you to another computer, and clearing the browser's site data removes them.
:::

## Write a report from your dashboards

A dashboard answers "what do the numbers look like"; a report answers "what should we take from them".

1. In the project, open **Reports** and select **Generate with AI**.
2. Select one or more dashboards and describe what you want the report to cover.
3. Once it exists, open the report and use **Chat** to work on it conversationally — ask for a different emphasis, a shorter summary, an added section.
4. The report's **Actions** menu holds **Edit**, **Duplicate**, **Download**, and **Delete**.

## Show a dashboard inside a Knowledge

A dashboard doesn't have to stay in the BI area. It can be rendered inside a [Knowledge as a custom view](/operational-guides/knowledge-custom-views), so the people working with the documents see the numbers next to them — with the dashboard's own auto-refresh interval respected.

## Result

You have a Rational BI project pointed at its sources and Knowledges, with the sensitive tables restricted to the people who should see them and suggested questions to get the chat going. You have dashboards you can either generate from a conversation or lay out by hand with headings, text, and dividers, charts tuned down to their type, colors, and basemap, an auto-refresh interval that keeps an open dashboard current without regenerating anything, exports to PDF, CSV and Tableau, pins for the dashboards you open every day, and reports that turn those dashboards into something you can send to somebody.

# Use Chat

**Chat**, the tab the Control Room opens on, is where you and your colleagues talk to Rational AI: by default to the **workspace assistant**, or to any touchpoint you can use.

:::note[Who Chat is for]
Chat is for the people in your organization who sign in to the Control Room. Every signed-in user can open it: it needs no license module and no permission. Your customers never see this page. They reach a [touchpoint](/operational-guides/configure-touchpoints) through its channels (a website widget, Telegram, email and so on), and staff review those conversations in [Conversations](/operational-guides/conversations).

Each chat is tied to one touchpoint, which decides the model, the knowledge and the options you get. The workspace assistant is the touchpoint Rational AI creates for every workspace: in the picker it appears as **Rational Chat**.
:::

## Chat and the other chats

Several places in Rational AI have a chat. This guide covers **Chat** only. A Knowledge has its own **Chat** panel on its page, a BI project has an AI chat beside its dashboards, [Conversations](/operational-guides/conversations) is where staff review and take over the conversations touchpoints have with your users, and Agents have chats of their own.

Chat and the chat inside a Knowledge use the same conversation view, so answers, sources, versions, Canvas and export work the same way. They differ here:

| | Chat | Chat inside a Knowledge |
|---|---|---|
| **Where** | The **Chat** tab | **Chat** on a Knowledge's page |
| **Who can open it** | Every signed-in user | People who can open that Knowledge (needs the Knowledge module in your license) |
| **Touchpoint** | The workspace assistant (**Rational Chat**) by default, or any enabled touchpoint you can use | The Knowledge's own touchpoint |
| **Chat list** | Your own chats, grouped by day. Administrators, and roles that can see all conversations, see every chat in the workspace | Only the chats with the Knowledge's touchpoint |
| **Context sent with each message** | What you add in the composer | The Knowledge's current filters (categories, tags, relations) and the nodes you selected in the graph |
| **Composer options** | Attachments, Canvas, **Advanced mode**, **Skills**, the reasoning level, plus **Knowledge bases**, **Web search**, **Deep Research**, **Voice conversation**, the model list and **Memory** | Attachments, Canvas, **Advanced mode**, **Skills** and the reasoning level. No **Knowledge bases**, **Web search**, **Deep Research**, **Voice conversation**, model list or **Memory** |

To chat with one Knowledge and send your current filters and selection with each question, use its own panel. See [Start a chat with your Knowledge](/operational-guides/create-knowledge#start-a-chat-with-your-knowledge).

## Prerequisites

- **A Control Room account.** Anyone who signs in can open **Chat** and start a chat.
- **To keep writing in a chat:** a role with **Update** on **Conversations**. Without it you can start a chat but not send further messages, dictate, rate, regenerate, edit or branch in it.
- **A working workspace assistant.** It needs an enabled default conversational model in the [AI Model Registry](/operational-guides/ai-model-registry-features). If it can't start, the page shows *"The default assistant could not be loaded."* and you can still pick another touchpoint.
- **For attachments:** images, PDF, text, Markdown, CSV, JSON, or Word, Excel and PowerPoint files in `.docx`, `.xlsx` and `.pptx` format.

## Start a new chat

The Chat page opens on the workspace assistant, ready for a new chat.

1. Select **New chat**. It always starts on the workspace assistant.
2. To talk to another touchpoint, select the assistant's name at the top of the page and pick one. **Rational Chat** (the workspace assistant) comes first, followed by the enabled touchpoints you can use, by name.
3. A greeting with your first name sits above the composer, for example *"Good evening, Alex"* or *"What's on your mind?"*. It changes with the time of day.
4. Type your question. If the touchpoint offers suggested questions, up to three appear below the composer: selecting one puts it in the message box, and you send it.

Nothing is created until you send the first message.

## Shape your request in the composer

Everything that changes how a request is handled lives in the composer, one message box shared by the new-chat screen and every conversation. The **+** button (*"Open tools menu"*) opens the options; each one you turn on shows as a chip in the composer, and its **✕** turns it off again.

<img
  src={require('@site/static/img/screens/chat-tools-menu.png').default}
  alt="The composer with the + menu open: Add files and photos, Knowledge bases, Web search, Deep Research, Canvas, Voice conversation, Advanced mode, Memory, Skills and Tools"
  style={{ width: '100%', maxWidth: '700px', border: '1px solid #E4E4E7', borderRadius: '6px', boxSizing: 'border-box' }}
/>

| Option | What it does |
|--------|--------------|
| **Add files and photos** | Attach files to the message. See [Attach files to a message](#attach-files-to-a-message). |
| **Attach page** | Attach the web page the Rational AI browser extension captured. Appears only when there is one. |
| **Knowledge bases** | Choose which knowledge the assistant searches, or see which it can use. See [Choose the knowledge to search](#choose-the-knowledge-to-search). |
| **Web search** | Have the assistant look things up on the web for this request. Works only with the workspace assistant. |
| **Deep Research** | Have the assistant investigate a question in depth, across many sources. Works only with the workspace assistant, and only when its **Canvas mode** is on. |
| **Canvas** | Generate a web page or design in the [Canvas](/operational-guides/agent-skills#preview-web-pages-in-canvas) panel beside the chat. Offered when the touchpoint's **Canvas mode** is on. |
| **Voice conversation** | Talk with the assistant out loud: it listens, answers and reads the answer back. On the new-chat screen, offered only for the workspace assistant. |
| **Advanced mode** | Show the technical detail behind each answer. See [Follow how an answer was built](#follow-how-an-answer-was-built). |
| **Memory** | On a new chat with a touchpoint that keeps [memory](/operational-guides/touchpoint-memory), start it with memory switched off (the chip reads **Memory off**). |
| **Skills** | Pick a skill for this request. It's the same list you get by typing `/`. |
| **Tools** | On a new chat, see which tools the assistant can use. |

Options the touchpoint doesn't offer don't appear. While an answer is generating, the send button becomes **Stop generating**; the text written so far is kept, with *"Generation stopped before the answer was finished."* and **Regenerate response** beneath it.

### Choose the model and reasoning level

The button next to the send button (*"Model and reasoning"*) shows the model and reasoning level in use, for example *gpt-5, Medium*. Select it to change them.

1. Under **Model**, pick another model. Use **Search models** to find one. Selecting the current model again returns to the default. The new model answers from your next message.
2. Under **Reasoning**, pick how hard the model thinks before answering: **Off**, **Minimal**, **Low**, **Medium**, **High**, **XHigh** or **Max**. Only the levels the model supports are shown. Selecting the highlighted level again returns to the touchpoint's default.

:::note[The touchpoint decides what you can change]
You can choose the model only in your own chats with the workspace assistant. In other chats the list may still appear, but a change is refused with *"The change could not be saved"*. The reasoning level can be changed on any touchpoint whose owner allows it; otherwise the popover shows the level as *"… set by the assistant"*. Either choice applies to this conversation only. See [Tune answer generation](/operational-guides/touchpoint-generation).
:::

### Choose the knowledge to search

In your own chats with the workspace assistant, you decide which of your knowledge bases a request searches.

1. Open **+** → **Knowledge bases**.
2. Select the knowledge bases to use; **Search knowledge bases** filters a long list, and the counter shows how many are selected.
3. To go back to searching everything you can read, select **Use all**.

The chip shows the knowledge base's name, or how many are selected. The selection never gives access to anything you can't already read.

Other touchpoints search the knowledge they were configured with. On the new-chat screen, **Knowledge bases** shows it read-only as **Available knowledge**. Inside an existing chat with another touchpoint, the picker still appears, but a change is refused with *"The change could not be saved"*.

### Pick a skill with `/`

Type `/` in an empty composer to list the skills enabled on the touchpoint, keep typing to filter, and press **Enter** to pick one. The skill becomes a chip at the start of your message, and the assistant is told to follow that skill for this request. See [Pick a skill with `/`](/operational-guides/agent-skills#pick-a-skill-with-).

## Send and queue messages

You don't have to wait for one answer to finish before lining up your next thought.

1. Type your message in the composer and send it.
2. While the assistant is still generating its response, a second message can't be sent in parallel. Instead it's **queued** and shown as a chip under **Queued**, above the input.
3. Queued messages are sent **automatically and in order** as soon as the previous turn completes.
4. To cancel a pending send, hover the chip and select the **✕** (*"Remove from queue"*). Hovering also shows the tooltip **"Message waiting to be sent"**.

Queued messages are kept if you reload the page or switch to another chat.

## Attach files to a message

Attach images and documents to a message so the assistant can use them directly in its answer.

1. Open **+** → **Add files and photos**, or drag files onto the composer. Images, PDF, text, Markdown, CSV and JSON files are accepted, and Word, Excel and PowerPoint files in `.docx`, `.xlsx` and `.pptx` format (not the older `.doc`, `.xls` and `.ppt`). Each file can be up to 25 MB; see [Limits and quotas](/reference/limits#chat-and-attachments).
2. A card for each attachment appears in the composer while it uploads; the send button waits until every upload has finished.
3. Send the message. The attachments appear above your message in the history.

The assistant sees images when the model supports them, and reads the text of documents.

:::note[The touchpoint decides whether files are allowed]
**Add files and photos** appears only when the touchpoint allows attachments. A file of another type is refused with *"Unsupported file type. Attach an image, PDF or text document."*
:::

### Open an attachment

The attachment on a message is a button: select it to get the file itself, not only its name. It opens in a new browser tab, where the browser previews what it can (PDFs, images, text) and downloads the rest.

This matters most for files you never had a local copy of. When a conversation arrives through a [channel](/operational-guides/manage-channels) (a document mailed in through an [Email channel](/operational-guides/connect-email), a PDF sent to a [Telegram bot](/operational-guides/connect-telegram)), the attachment is the only route to what the sender sent.

:::note[Large corpora belong in a Knowledge]
Document extraction is bounded by size, page, and character caps. For large or numerous documents you want the assistant to search over, store them in a [Knowledge](/operational-guides/create-knowledge) instead. Rational AI indexes that content for retrieval-augmented answers ([RAG](/concepts/RAG)), where the assistant looks up relevant passages at answer time rather than reading whole files inline.
:::

## Follow how an answer was built

While the assistant works, a line above the answer reads *"Rational AI is thinking..."* with a live summary of what it's doing. When it's done, everything it did before answering (reasoning, knowledge searches, web searches, tools and skill runs) is folded into that single line, for example *"Thought for 8s"* or *"Thought for 12s, used skill xlsx, 4 steps"*. Select it to read the steps in order.

- A **knowledge search** reads *"Searched 2 knowledge bases and read 5 documents"*.
- A **tool** reads *"Used …"* with the tool's name.
- A **skill run** lists its steps in plain words; see [Follow what happened](/operational-guides/agent-skills#follow-what-happened).
- A run that failed part-way is titled *"…, stopped at step …"*.

### See the technical detail with Advanced mode

Turn on **+** → **Advanced mode** when you need to understand or debug an answer. The steps then show their technical detail, including the three phases of each knowledge search:

| Phase | What happens |
|-------|--------------|
| **Initial Retrieval** | Finds the documents most similar to the question using semantic search. |
| **Graph Expansion** | Adds related documents by following the knowledge graph from those results. |
| **Final selection** | Ranks everything by relevance and keeps what fits in the model's context. |

When an answer fails, Advanced mode also shows the raw error instead of *"The response could not be completed."*

:::note[Only administrators see what a tool was sent and returned]
For everyone else, tool calls keep their names but lose their arguments and raw output: in the chat, in Advanced mode and in an exported chat alike. Tool arguments can carry internal identifiers or data the person chatting shouldn't see. Widgets the chat renders, and tools that run in the browser, are not affected.
:::

## See the sources behind an answer

When an answer used your knowledge or the web, a sources pill appears under it, showing how many knowledge resources and how many web pages the model was given.

1. Select the pill. The **Sources** panel opens beside the chat (over it, on a narrow window).
2. Under **Internal resources**, each entry shows the knowledge base, the resource and an excerpt; select it to open the resource in its Knowledge.
3. Under **Web**, each entry shows the site, title and snippet; select it to open the page.

Select the pill again, or **Close**, to hide the panel.

## Work with answers: Actions and branches

Beyond reading a reply, you can regenerate it, rewrite your own question, branch it into a new chat, and compare different versions.

Under each AI message are **copy**, the thumbs-up / thumbs-down pair for feedback, **Regenerate response**, the sources pill, and **‹ ›** arrows with a version counter (for example **1/2**) when alternatives exist. The **⋯** menu shows which model generated the answer and adds **Read aloud**, **Verify response** and **Branch into a new chat**.

:::note[Some actions depend on the touchpoint]
Regenerating, editing and verifying are each switched on per touchpoint. Sending more messages, rating, regenerating, editing and branching need **Update** on **Conversations**. An action that isn't available doesn't appear.
:::

### Generate an alternative answer

Use this when an answer is close but you'd like to see how the assistant would phrase it differently.

1. On an AI message, select **Regenerate response**.
2. A new version is added and the counter updates (for example **2/2**). The chat auto-advances to the newest version.
3. Use the **‹ ›** arrows (**Previous version**, **Next version**) to move between versions. If you navigate back to an older version and regenerate again, you stay on the version you were viewing.

### Edit your message to branch

Use this when you want to rephrase a question and explore a different line of conversation without losing the original.

1. On one of your own messages, select **Edit**.
2. An inline edit box opens with the hint *"Saving creates a new version of this conversation."*
3. Adjust the text and select **Save** (or press Enter).
4. A new version is created and the assistant answers it. Attachments on the original message are carried onto the new version, so they survive the edit.

### Branch into a new chat

Versions keep alternatives inside one chat. When you want to take a conversation somewhere else entirely (try another approach, hand a copy to yourself for a different task), branch it into a chat of its own.

1. On a finished AI message, open **⋯** → **Branch into a new chat**.
2. A new chat opens with the same title and touchpoint, containing the conversation up to and including that answer (only the versions you were viewing, not the alternatives).
3. Carry on from there. The original chat is untouched.

:::note[Files stay in the original chat]
The new chat keeps your choice of model and knowledge bases, but attachments and generated files stay in the original chat, and so do settings such as the reasoning level or memory being off.
:::

### Rate an answer

Tell the touchpoint's owners whether an answer worked. The two thumbs buttons on the action row open a short dialog rather than recording a silent vote, so a rating always comes with the reason behind it.

1. On an AI message, select **thumbs up** (*Give positive feedback*) or **thumbs down** (*Give negative feedback*).
2. For negative feedback, select as many reasons as apply under **Add details**: **Confusing**, **False**, **Offensive**, **Useless**, or **Other**.
3. Add an optional note: *"What was satisfying about this response?"* for positive feedback, *"What was unsatisfying about this response?"* for negative.
4. Select **Send**. A **Thanks for your feedback** toast confirms it, and the thumb you chose switches to its filled icon so you can see at a glance which messages you have rated.

:::note[Canceling sends nothing]
Closing the dialog with **Cancel**, the **✕**, or the Escape key sends nothing at all. No rating is recorded from opening the dialog alone. Only **Send** submits, and if it fails you are told so (*"Could not submit your feedback. Please try again"*) rather than being left thinking it went through.
:::

## When an answer stops early

An answer that ends before it should says why, in a strip under the text, and most strips carry a **Regenerate response** button.

| Message | What happened |
|---------|---------------|
| *"Generation stopped before the answer was finished."* | You selected **Stop generating**. The partial answer is kept. |
| *"Answer cut short: the model reached its output limit."* | The answer hit the maximum length. |
| *"Answer cut short: the generation ran past its time limit."* | The answer took too long and was cut. |
| *"Generation stopped: the model used up its output allowance before writing an answer."* | The model spent its whole budget thinking. |
| *"Generation stopped after … tokens because the model kept repeating itself."* | The model started looping and was stopped. |
| *"Generation stopped: the tool "…" ran out of time on every attempt."* | A tool never answered in time. |
| *"Generation stopped because the tool "…" failed … consecutive times."* | A tool kept failing; check the failed step in the timeline before trying again. |
| *"This assistant cannot answer: …"* | An administrator blocked the assistant or its model. There is nothing to regenerate. |
| *"The response could not be completed."* | Any other error. Select **Retry**. |

If the same message keeps coming back, the touchpoint's owner can adjust its limits. See [Tune answer generation](/operational-guides/touchpoint-generation#what-users-see-when-generation-stops-early).

## Check an answer against your knowledge

On touchpoints with response verification switched on and the knowledge search tool enabled, you can check an answer, sentence by sentence, against the knowledge documents retrieved for the conversation.

1. On an AI message, open **⋯** → **Verify response**. **Verifying** shows while it runs.
2. Each checked sentence of the answer is highlighted: **green** for **Supported**, **yellow** for **Unsupported**, **red** for **Disproven**.
3. Hover a highlighted sentence to see its state.
4. Select a highlighted sentence to open **Response verification**. Sentences are grouped under **To check** (disproven and unsupported) and **Supported**. For the selected sentence, **Sources** lists the excerpts it was compared with, each with its knowledge base and a **high match**, **medium match** or **low match** label.

Select **Verify response** again to hide the highlights. If nothing in the answer can be checked, the action row shows **No verifiable sentences**. If the check fails, select **Verification failed, retry**.

:::note[Unsupported isn't the same as wrong]
Verification measures how close the answer is to the excerpts from the knowledge bases consulted, not whether it is true. Treat an unsupported or disproven sentence as a cue to look closer, especially for anything the answer took from general knowledge rather than from your documents.
:::

## Work with the files the assistant creates

Documents the assistant writes for you (a Word report from a skill, a page built in Canvas) open in the **Canvas** panel beside the chat. Select the file's name at the top of the panel to open its menu:

| Action | What it does |
|--------|--------------|
| **Download as Word / Excel / PowerPoint** (or **Download**) | Saves the file. |
| **Download as PDF** | Converts an Office file to PDF. Available when the Office editor is installed. |
| **Rename** | Renames a document created in the conversation. |
| **Open in a new tab** | Opens an Office file in its own browser tab. |
| **Save to knowledge** | Adds a copy of the file to a knowledge. |
| **Switch file** | Moves to another file of the conversation, created or attached. |
| **Delete** | Deletes a document created in the conversation, with its earlier versions. This can't be undone. |

The **‹ ›** arrows in the panel header move between the file's versions.

### Save a file to a knowledge

A file that matters shouldn't stay buried in a chat.

1. Select **Save to knowledge** in the file menu, or on the file's card under the answer.
2. Pick the knowledge (use **Search knowledge** if you have many). The file is saved as soon as you select it.
3. A *"Saved to …"* toast confirms it, with **Open in the knowledge**.

A copy is added to the knowledge and processed like any upload; the file stays in the conversation too. **Save to knowledge** appears only if you can edit at least one knowledge.

### Edit Office documents

When the Office editor is available on your installation, Word, Excel and PowerPoint files open for editing directly in the Canvas panel.

- The toolbar offers **Alignment**, **Lists**, **Insert** (**Table**, **Link**, **Page break**, **Header and footer**), **Comment**, and **More tools** for text colors and heading styles. On a narrow panel, more of the controls move into **More tools**.
- The mode menu at the top right switches between **Editing**, **Suggesting** (changes are tracked for review) and **Viewing**.
- *"Last saved at …"* in the file menu tells you when your edits were saved.

:::note[Without the editor you still get a preview]
If the Office editor isn't installed, Word and Excel files show a read-only preview and other formats offer a download. Without permission to update conversations, the document opens read-only, with a **Download** button.
:::

## Listen and dictate

The chat can read answers out loud and take messages by voice instead of typing.

### Read an answer aloud

Every assistant message carries **Read aloud** in its **⋯** menu. Select it and the answer is spoken, with an equalizer showing while it plays.

Markdown is stripped before anything is read, so fenced code blocks and link targets aren't spelled out character by character.

:::note[The voice follows the answer, not the interface]
An Italian answer is read in Italian even if you're using Rational AI in English. What's spoken is the language of the text, not the language of the UI.

:::

### Dictate a message

Press the **mic** button in the composer, or hold **Ctrl+Shift+D**. The composer becomes a recording bar with a live waveform and three actions: discard, stop, and send.

- **Stop** drops the transcript into the message box, so you can correct it before sending.
- **Send** posts it straight away.

Dictation works in both composers: inside an existing conversation, and on the new-chat screen, where the transcript starts the chat exactly as typed text would.

### Set the audio language

The arrow next to the mic button opens **Audio language**, with three options: **Detect automatically** (the default), **Italian**, or **English**. Your choice is remembered and applies to both dictation and reading aloud.

With **Detect automatically**, each recording is detected as it's transcribed, and the language of an answer is detected from the answer itself, falling back to your own locale only when a message is too short to identify.

Choosing **Italian** or **English** explicitly skips the detection pass, so transcription is faster. If you always dictate in the same language, pin it.

Inside an existing chat, dictating needs the same **Update** on **Conversations** as typing.

## Keep going in a long conversation

A model can read only so much of a conversation at once. When a chat gets that long, the assistant usually carries on from a summary of the earlier messages, and a divider marks the spot: *"The assistant now works from a summary of the messages above"*. Everything above it is still in your history; the assistant reads it in condensed form.

Some touchpoints stop instead: the chat says *"This conversation is as long as the assistant can follow."* and offers **New conversation**. The touchpoint's owner chooses which. See [Memory and long chats](/operational-guides/touchpoint-memory#choose-what-happens-when-a-conversation-gets-too-long).

## Find, rename and export your chats

The chat list shows your own chats. Administrators, and roles that can see all conversations (such as the built-in **Manager** role), see every chat in the workspace, including the conversations touchpoints have with your customers. Chats are grouped by the day they started: **Today**, **Yesterday**, **Previous 7 days** and **Older**. Chats with no messages are not listed. Use the search box to find one by its content. A dot next to a chat tells you when it **Needs your approval**, is **Working**, **Stopped with an error**, or is **Finished, not read yet**.

Each chat's **⋯** menu in the list has **Rename chat** and **Delete**. Select the chat's title at the top of the page for more: **Rename**, **Copy link to chat**, **Export chat**, **Memory**, and **Delete**. **Copy link to chat** copies a link that only people who can already read the chat can open.

### Rename a chat

Give a chat a clear title so you can find it later. Type one yourself or let the assistant name it for you.

1. Select **Rename chat** in the chat's **⋯** menu in the list, or **Rename** in the title menu.
2. Edit the title, or select the spark button (*"Generate with AI"*) next to the field. The generated title replaces the text, and the field is marked as AI-generated.
3. Select **Save**.

### Export a chat

Select the chat's title, then **Export chat**. A JSON file named after the chat downloads, with the chat's details and every event in it (messages, versions and steps), ready to archive or to process with your own tools.

:::note[An export shows what you are allowed to see]
The export applies the same rules as the chat: unless you are an administrator, tool calls appear without their arguments or raw output.
:::

# Back up and restore an on-premises installation

**Settings** → **Backup** copies all the data of an on-premises Rational AI installation to a destination you own (a network share, an S3 bucket, or an FTP or SFTP server), every day or on demand.

:::note[On-premises only]
The Backup page is on by default on every [on-premises installation](./on-premises-installation): it only needs a destination. On the managed cloud the platform backs the data up for you and the page is not shown.
:::

Every update also takes a local backup first, so a bad release can be rolled back. That backup stays on the installation's own disk, so it doesn't protect you from a lost machine or disk. Set up the backup on this page on every installation that holds data you care about.

## What a backup contains

A backup includes:

- Your workspace's application data: conversations, Knowledges, users, settings and stored credentials
- The search index behind your Knowledges
- Attachments, synced source files and extension packages
- The installed extensions
- The Rational BI and Knowledge databases

Each run creates a folder named after its UTC start time (`2026-09-09T02-30-00Z`). The backup holds stored credentials, so keep the destination as private as the installation itself.

The weights of the models the installation runs are not backed up: they download again after a restore. Sessions aren't backed up either, so after a restore everyone signs in again.

## Prerequisites

Before you start, make sure you have:

- **Administrative access.** The page is restricted to administrators.
- **A destination with enough space** for a full copy of the installation's data and files.

## Set the destination

Go to **Settings** → **Backup** and pick the destination **Type**. The fields change with the type:

| Type | Fields | Path |
|------|--------|------|
| **Network share (SMB / Samba)** | Host, port (445), user, password, domain | Share and folder, for example, `backups/rational` |
| **S3 bucket** | Endpoint, provider (`Other` for a NAS or MinIO, `AWS` for Amazon), region, access key ID, secret access key | Bucket and prefix, for example, `my-bucket/rational` |
| **FTP server** | Host, port (21), user, password | Folder |
| **SFTP server** | Host, port (22), user, password | Folder |

**Local folder (NFS mount)** is for a folder Rational AI has mounted on the installation for you. Ask the owner of the destination for an account that can write only the backup folder.

The folder is created on first use. Select **Test destination** before saving: it writes and deletes a small file there to check the credentials, the path and the write permission. A failure shows the reason, such as a wrong password, a read-only share or an unreachable host.

:::warning[Prefer SFTP or S3 over FTP]
Plain FTP sends the password and the data unencrypted. When the same server offers SFTP, use that.
:::

Passwords and access keys are stored encrypted. When you come back to the page they show as `********`; leave them as they are to keep the stored value, or type a new one to replace it.

## Schedule

**Daily backup** runs a backup every day at the **Time of day** shown, in the time zone of your browser at the moment you save. A run that is still going when the next one is due is not interrupted; the next one is skipped.

Pick a quiet hour, away from 03:00, when the installation updates itself. A Knowledge that changes during the backup can come back inconsistent.

## Retention

After each successful run the destination is pruned. Choose in **Keep** how much history to hold:

| Option | Keeps |
|--------|-------|
| **Last 7 backups** | The newest seven, whatever their age |
| **One month, a backup per day** | The newest seven, and one per day for 31 days |
| **Three months: daily for a week, then weekly** | The newest seven, and one per week for 13 weeks |
| **One year: daily for a week, weekly for two months, then monthly** | The newest seven, one per week for 9 weeks, and one per month for 12 months |
| **Everything, never delete** | Every backup |

A policy Rational AI set that matches none of these shows as **Custom**. Attachments and files are kept in one copy shared by every backup, which is never pruned, so files deleted from Rational AI stay at the destination.

Select **Save**. The **Next scheduled backup** line under **Last backup** confirms the schedule is registered.

## Back up now, and check it happened

**Back up now** starts a backup immediately. While it runs the page shows each component as it is captured; when it finishes, *Last backup* shows the time, the outcome, the size and the folder name, and the backup appears under **Backups at the destination**.

A failed run reports the error in place of the size. A backup that fails half-way is removed from the destination, so whatever is listed there is complete and restorable.

Check now and then that:

- **Last backup** keeps moving and says *completed*.
- **Backups at the destination** lists your backups. The list is read from the destination each time the page loads.

## Restore

Restoring replaces the current data with a backup and needs the application stopped, so Rational AI runs it for you. To ask for one, send Rational AI the name of the backup you want, as listed under **Backups at the destination** (for example `2026-09-30T01-30-00Z`).

:::danger[A restore overwrites everything]
All the data, files and extensions are replaced by the backup's contents. Anything created after that backup was taken is lost. Take a fresh backup first if there is any doubt.
:::

A restore needs the destination's settings, password included. Agree with Rational AI how it gets them when you set the destination up, not on the day you need a restore. **Copy restore command** on any backup copies those settings, with the secrets masked as `********`.

After a restore:

- Everyone is signed out: sessions are not part of a backup.
- Check a recent conversation, a knowledge base and an extension. Extensions may take a moment on first use while their packages are downloaded again.
- A backup goes back only into the release that took it, or a newer one.
- On a replacement machine, **Settings** → **Licence** may ask you to activate the license again.

### Rehearse it

Ask Rational AI to restore one into a spare installation once after setting the destination up, and again after major updates: it is the only way to know the destination is really usable.

## Limits

- **Backups are not encrypted.** Protect them with the destination's access control and disk encryption.
- **Not in the backup:** the installation's own secrets, its certificates and its connection to Rational AI. A replacement machine can't read the backups without those secrets.

## Troubleshooting

| Symptom | What to check |
|---------|---------------|
| **Test destination** fails with *permission denied* | The share or folder is read-only for the given user. |
| A backup shows *failed* | The error shown in place of the size. If it doesn't name the destination, contact Rational AI. |
| A component is *skipped* | The installation isn't set up to back that component up. Contact Rational AI. |
| The backups list is empty though runs completed | The destination path was changed after those runs: the list reads the current path. |

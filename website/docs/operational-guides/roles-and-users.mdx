# Manage roles and users

Roles decide what people can do in Rational AI. This guide shows you how to set a role's permissions, create users, organize them into groups, and remove them.

A **role** is a named set of permissions. A **user** is an account that signs in to Rational AI. A user can have several roles or none, and their permissions are the combination of their roles. **Admin** is not a role: it's a flag that gives a user every permission.

## Before you begin

- An **Admin** account, or a role with the matching rows: **Users** to manage users, **Groups** for groups, **Roles** for roles. Admins bypass every permission check, so the role matrix doesn't apply to them.
- Roles, users, and groups are in the **Access** group of **Settings**.

## Configure a role

1. Go to **Settings** → **Roles**.
2. Select the role you want to change.
3. In the matrix, find the feature row and select the cell for the action: **List**, **Read**, **Create**, **Update**, **Delete**, **Use**, or **Share**.
4. Choose how far the permission reaches:

   | Value | The role can act on… |
   |---|---|
   | **None** | nothing |
   | **All** | every item of that feature |
   | **Own** | items the user created, and items shared with them or one of their groups |
   | **Selected IDs** | only the items you pick from the list |

   The **Create** column offers only **None** and **All**.

Each cell changes one permission only. Review the whole row for a feature, because **Read** without **List**, for example, lets someone open an item but not find it.

### Grant access to Rational BI

[Rational BI](/operational-guides/rational-bi) uses four rows of the matrix:

| Row | Controls |
|---|---|
| **BI projects** | The project list, and opening, creating, and deleting projects |
| **Dashboards** | The dashboards inside a project |
| **Reports** | The reports generated from dashboards |
| **BI defaults** | The workspace-wide configuration under **Settings** → **Rational BI** → **BI defaults** |

To let a role build BI content, grant **Create** and **Update** on **BI projects**, **Dashboards**, and **Reports** together. With **BI projects** alone, people can open a project but find it empty. Leave **BI defaults** to admins, because every project inherits it.

### What people see without a permission

The interface hides what a role can't do:

- **Settings** sections the role can't access stay in the sidebar but are disabled, with the hint "You don't have access to this section".
- Without create, update or delete permission, the matching **New** button, row menu items and **Save** button don't appear, and forms open read-only.
- Opening a link to a page the role can't read shows "Access denied".

Sections your license doesn't include, such as **Rational BI**, **Knowledge** or **Gen**, are hidden for everyone, whatever their role.

:::tip
To check a role, create a test user with only that role and sign in as them. Every disabled **Settings** section is a permission the role doesn't have.
:::

## Create a user

1. Go to **Settings** → **Users** and select **Add** → **Create user**.
2. In **Create new user**, enter **Name**, **Surname**, **Email address**, and **Confirm email address**.
3. In **Role**, select one or more roles. Select **Admin** to make the user an administrator, or **User** for an account with no role.
4. Keep the generated **Temporary password**, or enter your own. Select **Copy** to copy it so you can share it with the user.
5. Leave **Require password change at first login** selected so that the user sets their own password when they first sign in. If you clear it, the password you set stays valid until the user changes it.
6. Select **Create**.

## Share access through groups

Groups don't carry permissions. What a user can do always comes from their roles. Groups decide **which items** a user reaches when their role has the **Own** scope. If you share a Knowledge, a touchpoint or another item with a group, every member can use it as if it were their own.

1. Go to **Settings** → **Groups** and select **New**.
2. Enter a **Name** and a **Description**.
3. In the users table, select the members. Turn on **Only members** to show only the users already in the group.
4. Select **Save**.

## Remove a user

The row menu on the **Users** page has two ways to remove someone:

- **Delete user**: for someone who leaves the organization. Their conversations are kept.
- **Erase all data**: for someone who exercises a right to erasure. Their conversations are deleted too, permanently.

Both are recorded in the [audit trail](/operational-guides/audit-trail). For how they differ in detail, and how to erase someone's data, see [Erase a person's data](/operational-guides/erase-personal-data).

Users can also disable or delete their own account. See [Manage your own account](/operational-guides/manage-your-account).

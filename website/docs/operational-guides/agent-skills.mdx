# Use skills in chat

A skill is a packaged way of doing one kind of job, such as building a spreadsheet, writing a Word document or designing a web page. When you ask for that job in a chat, the assistant follows the skill's instructions and hands you the finished file. This guide shows how to use skills in **Chat** and in a Knowledge's chat, and how a builder makes them available.

Skills belong to a [touchpoint](/operational-guides/configure-touchpoints), the assistant that answers a conversation, so you see the skills of the touchpoint your chat runs on. They are separate from the skills of the agents in the [Agents](/cr/Agents) section, which are granted in **Agents** → **Library** (see [Build an agent](/operational-guides/create-an-agent#browse-the-library)).

## Prerequisites

- **To use skills:** a chat whose touchpoint has at least one skill.
- **To add skills to a touchpoint:** a role with **Update** on **Touchpoints**. Skills come from [extensions](/operational-guides/manage-extensions), which an administrator installs.

## Ask for a job

You don't have to name a skill. Ask for what you want in plain language, for example *"build a household budget spreadsheet"*, and the assistant decides whether one of the touchpoint's skills fits and runs it.

### Pick a skill with `/`

When you know which skill the job needs, choose it yourself.

1. In an empty composer, type `/`. A **Skills** menu lists the skills enabled on the chat's touchpoint, with a description of the highlighted one.
2. Keep typing to filter by name, then pick a skill with a click, **Enter** or **Tab**. **Esc** closes the menu.
3. The skill becomes a chip at the start of the message. Type your request after it and send.

The same list is under **Skills** in the composer's **+** menu, which keeps any text you have already typed. To drop the skill before sending, select the chip's **✕**, or press **Backspace** in an empty composer.

Picking a skill tells the assistant to follow that skill for this request; your text after the chip is still what it acts on. If the menu says *"No skills are enabled for this chat"*, the touchpoint has no skills yet.

### Follow what happened

The skill's work appears in the collapsed line above the answer, for example *"Thought for 12s, used skill xlsx, 4 steps"*. Open it to read the steps in plain words: reading the skill instructions, writing and running a script, saving a file, and any attempt that failed and was retried. Files the skill made along the way are listed under the working files, each with **Download**.

The file you asked for gets a card under the answer, with its type, name and size:

- **Open** shows it in the [Canvas](#preview-web-pages-in-canvas) panel, for types that can be previewed.
- **Download** saves it.
- **Save to knowledge** files it into a [Knowledge](/operational-guides/create-knowledge).

If the skill stops before producing its file, the answer says *"No file was created."* From there you can open **Technical details**, retry, or select **Change model**, which helps when a smaller model struggles with a long skill.

## Preview web pages in Canvas

When a skill builds a web page or an SVG image, **Canvas** shows it live in a panel beside the conversation.

1. In the composer's **+** menu, select **Canvas** before sending. A **Canvas** chip appears in the composer.
2. Ask for a web page or a design.
3. When the page is ready, the Canvas panel opens on its own.

The assistant also uses Canvas for web and UI requests sent without the chip. The **Canvas** item appears only when the touchpoint has **Canvas mode** turned on.

In the panel, switch between **Preview** and **Code**, move between versions with **Previous version** and **Next version**, and use **Fullscreen**, **Refresh**, **Copy**, **Download** and **Close**. Versions are saved in your browser. The preview runs only in the chat: someone reviewing the conversation in [Conversations](/operational-guides/conversations) sees no Canvas panel.

## Add skills to a touchpoint

1. Make sure the extension that ships the skill is installed (**Settings** → **Extensions**). Uninstalling an extension removes its skills.
2. Go to **Settings** → **Touchpoints** and open the touchpoint.
3. Open the **Skills** tab. Its table lists the skills already enabled, with their **Skill**, **Description**, **Version** and **Extension**.
4. In the **Add skill** picker, where skills are grouped by extension, select the skills you want.

To stop offering a skill, select **Remove skill** in its row's menu. The skill stays installed for other touchpoints.

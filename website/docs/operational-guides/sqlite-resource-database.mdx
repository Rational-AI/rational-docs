# Work with a SQLite resource database

Most files in a [Knowledge](/operational-guides/create-knowledge) can only be downloaded. SQLite files are different: Rational AI opens the database, renders it right inside the resource detail panel, and lets you explore and change the data without ever leaving the Control Room. This guide covers everything you can do there — browsing tables, running SQL, and editing values in place.

<Admonition type="info" icon="📖" title="WHAT IS A SQLITE RESOURCE DATABASE?">
SQLite is a lightweight database packaged as a single file. When a resource is a SQLite file, Rational AI ingests it by loading that file into a *knowledge database* — an internal database (a sqld namespace) named after the resource. The **SQLite resource database viewer/editor** connects to that knowledge database using its `knowledgeId` and database name, so the tables, views, and rows you see are the live contents of the resource.
</Admonition>

## Prerequisites

Before you start, make sure you have:

- **A Knowledge** containing at least one **SQLite resource** — a resource whose file is recognised as SQLite by its extension or MIME type.
- **Access** to that Knowledge and its resources in the Control Room.
- The resource **fully ingested**, so the worker has finished creating its knowledge database.

## Open the viewer

You don't switch anything on — the viewer appears on its own whenever a resource's file is recognised as SQLite.

1. Open the **Knowledge** tab and select the **card** for the Knowledge that holds your SQLite resource.
2. In **Table view**, open the resource's **details drawer** by clicking its row (or choosing **See details** from the options menu).
3. The resource viewer renders the **SQLite resource database** inline. The database name shown is the resource name the worker created.

<Admonition type="note" icon="📝" title="NO DOWNLOAD REQUIRED">
For ordinary resources, the original file is download-only. Because a SQLite resource is loaded into a knowledge database, you explore its data directly in place — no download, no separate database tool.
</Admonition>

## Explore the data

The viewer lays out the database's structure as tabs along the tab bar, with the selected object's rows shown in a grid below. From here you can move between tables, reorder rows, and narrow down what you see.

### Browse tables and views

Select a **table** or **view** tab to load its contents into the grid. Switching tabs is how you move between the different objects in the database.

### Sort rows

Use the **sort arrows** in any column header to order rows by that column. The arrow shows the current state: **up** for ascending, **down** for descending, and **both** when the column is unsorted.

### Filter rows

Select the **filter glyph** in a column header to add a filter row beneath the header, then type to narrow the rows down to matching values.

<Admonition type="note" icon="📝" title="CONTROLS STAY REACHABLE">
Column headers always keep their sort and filter icons visible. If space is tight, the column *name* ellipsizes rather than the controls, so you can always sort and filter — even on narrow columns.
</Admonition>

### Inspect a schema

When you need the exact definition of a table or view — its columns, types, and constraints — view its schema rather than guessing from the data.

1. Open the **Actions** menu next to the search box.
2. Select **View schema** to see the DDL (the SQL statement that defines the object). This works for both **tables** and **views**.

## Run SQL

When sorting and filtering aren't enough — joins, aggregates, or your own custom query — write SQL directly against the database.

1. Enter a statement in the viewer's **SQL** input.
2. Run it. The statement executes against the knowledge database through the backend `executeKnowledgeDatabase` connector (statements can also be sent in bulk via `batchExecuteKnowledgeDatabase`), so it runs against the resource's sqld namespace.
3. The grid updates with the result.

<Admonition type="note" icon="📝" title="IDENTIFIERS WITH SPACES">
Column and table names that contain spaces — for example `"Location HQ"` — are supported. Wrap such identifiers in double quotes in your SQL so they resolve correctly.
</Admonition>

## Edit data inline

Need to fix a value? You can change it directly in the grid instead of writing an `UPDATE` statement.

1. Click a **cell** to edit its value in place.
2. Confirm the edit to persist the change to the knowledge database.

## Result

You can browse the tables and views of a SQLite resource, sort and filter rows, inspect schemas, run SQL, and edit values inline — all from the resource detail panel in the Control Room, with every change applied directly to the resource's knowledge database.

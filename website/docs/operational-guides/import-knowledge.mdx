# Import records from Excel or CSV

Turn each row of an Excel or CSV file, such as a customer list, a contract register, or an asset inventory, into a record of a Knowledge. The import creates the attributes and the collection it needs on the way. To move a whole Knowledge between environments instead, see [Export and import a Knowledge](/operational-guides/export-knowledge).

## Prerequisites

- **Update** on the **Knowledge** row of your role. See [Manage roles and users](/operational-guides/roles-and-users).
- A file in `.xlsx`, `.xls`, `.csv`, `.tsv` or `.txt` format, up to 10 MB and 5,000 rows, whose first row names the columns.

## Import the file {#import-records-from-excel-or-csv}

1. Open the Knowledge's **Grid** (see [Collections and grid views](/operational-guides/knowledge-collections-and-grid)) and select **Import from Excel or CSV** in the toolbar. An empty Knowledge offers the same button in the middle of the page.
2. Drop the file in the dialog, or select the drop area to choose it. The file is read in your browser; CSV separators (comma, semicolon or tab) and encodings are detected for you.
3. If the workbook has several sheets, choose the **Sheet**.
4. Under **Import into**, choose a collection, **No collection**, or **New collection** with its name. The collection open in the grid is preselected.
5. For each **Column in the file**, check **Import as**: **Name** (the column that names the records), an existing attribute, **New attribute** with the **Type** to create it with, or **Do not import**. Rational AI proposes a mapping from the headers and sample values: a column named like an attribute goes to it, and the others become new attributes of the type their values suggest.
6. When numbers or dates are ambiguous, choose the **Decimal separator** (*1.234,5* or *1,234.5*) or the **Date order** (day first or month first).
7. Select **Preview**. The preview shows the first 100 rows, with values that don't fit their attribute marked in red. If some rows have invalid values, choose **Skip the rows with invalid values** or **Import them, leaving the invalid values empty**.
8. Select **Import N resources**.

When the import finishes, a toast confirms how many resources were imported and the grid switches to the collection that received them. Each record's **History** marks the values as written *via import*.

Every row creates a new record: the import doesn't update an existing record with the same name. To refresh data you imported earlier, edit it in the grid, or delete the old records first. If an import stops part way, the dialog says how many records were created and offers **Import the remaining N**, which carries on without duplicating them.

## Fill people and links by name

Columns that go to [person and link attributes](/operational-guides/knowledge-attributes) are matched by name, so the spreadsheet doesn't need IDs.

- **People** are matched to the users who can read the Knowledge, by the name shown in the grid (not case sensitive). A name that matches nobody is flagged in the preview as an invalid value.
- **Links** are matched to the records of the linked collection by name. A name with no match becomes a new record in that collection, and the preview lists it under *"Not in … yet, so the import creates them there"*.
- To put several people or records in one cell, separate them with a **semicolon**. Commas are allowed inside names.

Each person the import names receives a single notification, *"You were assigned to N records in …"*, rather than one per record.

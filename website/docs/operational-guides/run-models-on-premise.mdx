# Run models on your own servers

An on-premises installation runs its AI models on your own machines, so prompts and documents never leave them. You choose and deploy every model from **Settings** → **AI Model Registry**, as in the cloud.

## Prerequisites

- **An on-premises installation**, with administrative access to the Control Room.
- **Hardware for the models:** an NVIDIA GPU for good speed, or enough memory to run small models on the CPU.
- **A Hugging Face token, for gated models only:** models such as Llama or Gemma need your organization's own token, which Rational AI sets on the installation. Public models (for example `BAAI/bge-m3`) need none.

## Add your first models

A new installation starts with **no models**: no embedding model and no chat model. Until you add them, a Knowledge can't index documents and chats can't answer.

1. Go to **Settings** → **AI Model Registry** and select **Add new** → **Choose an open source model**.
2. Add an **embedding model** first, for example `BAAI/bge-m3`, and deploy it.
3. Add a **text generation model** that fits your hardware, and deploy it.
4. In the **Default models** panel of the same page, set the **Embedding model** and the **Conversational model** to the models you added.

Each deployment downloads its weights first, then starts; the **Deployment** section of the model follows it to **Ready**. For deploying, scaling and stopping models, see [Deploy and run self-hosted models](/operational-guides/model-deployments).

If every answer from a new chat model fails, check the tool-call parser and reasoning parser in its **Deploy settings**. Rational AI fills them in for the model's family, and chats need them because they give the model tools.

## Understand GPUs and memory

- **With an NVIDIA GPU**, a text generation model gets one GPU unless its deploy settings say otherwise.
- **Without one**, models run on the CPU. That works, but much more slowly, so keep CPU deployments to embedding models and small chat models.

You can change the number of GPUs in a model's deploy settings; `0` runs it on the CPU.

Each model reserves a share of its GPU's memory, set by its **GPU memory budget**: a share (`85%`), a size (`24GiB`) or both (`100% - 1.5GiB`). When several models share a GPU, give each its own budget so that they fit together.

A model's weights download once and are kept across restarts. [Backups](/operational-guides/backup-and-restore) leave the weights out, since they can be downloaded again.

## Run models on a DGX Spark

An NVIDIA DGX Spark shares one pool of memory between its GPU and the rest of the system. The installation recognizes it and leaves 80 GiB of that memory to models, keeping the rest for Rational AI. A model's GPU memory budget counts against those 80 GiB, so `50%` means 40 GiB.

If the budgets of the models you deploy add up to more than 80 GiB, they don't all start. Size the budgets so that the models you want running at the same time fit together.

## Add more machines

If one machine doesn't have enough GPUs for every model you need, Rational AI can add machines that only run models. You keep deploying from **Settings** → **AI Model Registry**, and each model runs wherever there is room for it.

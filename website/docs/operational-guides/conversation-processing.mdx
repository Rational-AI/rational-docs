# Configure conversation processing

Rational AI can quietly enrich every end-user conversation while it happens: giving it a title, tagging its topics, gauging how the user feels, and summarising it for an operator. This guide shows you where to turn each of these on, which model runs each one, and how to tune them.

:::note[What is conversation processing?]
Conversation processing is the work Rational AI does automatically behind the scenes on each conversation. It is the configuration behind the titles, topic chips, sentiment badges and summaries you see in the [Conversations list](/operational-guides/conversations) and in [chat](/operational-guides/chat-experience). These settings apply platform-wide.
:::

## Prerequisites

Before you start, make sure you have:

- **Administrative access:** an account with permission to change platform settings (see [Roles and users](/operational-guides/roles-and-users)).
- **AI models configured:** at least one active model in the [AI Model Registry](/operational-guides/ai-model-registry-features), so you have something to assign to each task below.

Open **Settings** → **Conversations** to begin. Each task has its own panel, described below.

:::note[Each part is optional and independent]
Title generation, topic detection, sentiment analysis and summary generation are separate background tasks. You can enable any combination of them, and none of them slows down the reply the user sees. Because each task is small and simple, it is usually sensible to give it a small, cheap [model](/concepts/LLMs) rather than your most capable one.
:::

## Choose the model for each task

Every task has its own model picker. You can pick a specific model, or one of two defaults that follow your configuration when it changes:

| Option | When to use it |
|---|---|
| **Platform default model** | One model for every conversation: the **Conversational model** set under [default platform models](/operational-guides/ai-model-registry-features#set-default-platform-models-per-task-type). |
| **Touchpoint default model** | Each conversation is processed by the model of its own [touchpoint](/operational-guides/configure-touchpoints). An empty picker means the same thing. |
| A specific model | You want a small, dedicated model for this task, whatever the touchpoint uses. |

:::note[A default with no model behind it skips the task]
A specific model always wins. With a default, the task runs only if that default actually points to a model: if no platform **Conversational model** is set, or a touchpoint has no model of its own, the task is skipped for those conversations rather than failing.
:::

The model that writes the replies users read isn't chosen on this page: it's the platform **Conversational model** in the [AI Model Registry](/operational-guides/ai-model-registry-features#set-default-platform-models-per-task-type), unless a touchpoint picks its own.

## Title generation

Title generation auto-names each conversation so you and your team can find it later in the [Conversations list](/operational-guides/conversations).

1. Turn on **Enable title generation**.
2. Choose a **Title generation model**.
3. Set the **Calculation frequency**: how often a title is produced, expressed as "every N messages". A larger number means the title is refreshed less often.
4. Set **Number of messages to consider**: how many of the most recent messages the model reads when it writes the title.
5. Leave the **Title generation template prompt** as provided, or adjust it. This is the instruction the model follows; it returns the title as a small JSON object (a tiny block of structured text the platform can read back reliably).

## Topic detection

Topic detection tags each conversation with the topics it covers, up to three, chosen from a list you define. This is useful for filtering, reporting (seeing what people ask about most) and routing (sending conversations to the right place).

1. Turn on **Enable topic detection**.
2. Choose a **Topics detection model**.
3. Set the **Calculation frequency** and **Number of messages to consider**, exactly as in title generation.
4. Build your **Topic list**. These are the labels the model can choose from, for example *Order Status*, *Billing Request*, and *Tech Support*. Remove a topic with its **×**, and add a new one with **New**.
5. Leave the **Topic detection template prompt** as provided, or adjust it. It instructs the model to return only labels from your list, written exactly as they appear there.

:::note[The platform enforces the answer shape, whatever the prompt says]
Rational AI always tells the topic model the exact format it must answer in: a single-line JSON object with at most three labels copied from your list. An older or customized prompt that asks for a different shape can no longer break classification. If your prompt predates this, select **Restore default** to bring it in line with the current wording.
:::

## Sentiment analysis

Sentiment analysis estimates how the user feels during the conversation, surfaced as a sentiment badge alongside it.

1. Turn on **Enable sentiment analysis**.
2. Choose a **Sentiment analysis model**.
3. Set the **Calculation frequency** and **Number of messages to consider**.
4. Adjust the **Sentiment list** if you need to: each sentiment has a label and a color, which is how it appears in the Conversations list.

## Summary generation

Summary generation lets an operator read a structured recap of a conversation before taking it over.

1. Turn on **Enable summary generation**.
2. Choose a **Summary generation model**. Thinking models are not recommended for this task.
3. Set **Number of messages to consider** (`0` means the whole conversation).

:::note[The prompt fields are advanced]
Each task's [prompt](/concepts/Prompts) field (the written instruction its model follows) ships with a sensible default, and **Restore default** brings it back. You only need to touch them if the automatic titles, topics, sentiment or summaries aren't coming out the way you want.
:::

## Result

When you are happy with your choices, select **Save** to apply them, or **Cancel** to discard them. From now on, the tasks you enabled run automatically on every new conversation across the platform, each with the model you picked or the default it follows, and their titles, topic chips, sentiment badges and summaries appear in the [Conversations list](/operational-guides/conversations) and in [chat](/operational-guides/chat-experience).

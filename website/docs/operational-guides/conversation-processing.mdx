# Configure conversation processing

Rational AI can give each conversation a title, tag its topics, gauge how the user feels, and summarize it for an administrator. These are the titles, topic chips, sentiment badges and summaries you see in [Conversations](/operational-guides/conversations) and in [Chat](/operational-guides/chat-experience).

The settings on this page are platform defaults. A [touchpoint](/operational-guides/configure-touchpoints) can override title generation, topic detection and sentiment analysis on its **Models** tab.

## Prerequisites

- **Administrator role:** the page opens for any role with access to **Conversations**, and roles with **Update** on it see **Save**, but only administrators can save changes (see [Roles and users](/operational-guides/roles-and-users)).
- **AI models configured:** at least one active model in the [AI Model Registry](/operational-guides/ai-model-registry-features), so you have something to assign to each task below.

Open **Settings** → **Conversations** to begin. Each task has its own panel, described below.

*Settings → Conversations: title generation, topic detection, sentiment analysis and summary generation, each turned on separately with its own model.*

Each task is turned on separately, and none of them slows down the reply the user sees. A small, inexpensive [model](/reference/glossary#large-language-model-llm) is usually enough for each.

## Choose the model for each task

Every task has its own model picker. You can pick a specific model, or one of two defaults that follow your configuration when it changes:

| Option | When to use it |
|---|---|
| **Platform default model** | One model for every conversation: the **Conversational model** set under [default platform models](/operational-guides/ai-model-registry-features#set-default-platform-models-per-task-type). |
| **Touchpoint default model** | Each conversation is processed by the model of its own [touchpoint](/operational-guides/configure-touchpoints). An empty picker means the same thing. |
| A specific model | You want a small, dedicated model for this task, whatever the touchpoint uses. |

With a default, the task runs only if that default points to a model. If no platform **Conversational model** is set, or a touchpoint has no model of its own, the task is skipped for those conversations.

The model that writes the replies users read is the platform **Conversational model** in the [AI Model Registry](/operational-guides/ai-model-registry-features#set-default-platform-models-per-task-type), unless a touchpoint picks its own.

## Title generation

Title generation names each conversation so you can find it later.

1. Turn on **Enable title generation**.
2. Choose a **Title generation model**.
3. Set the **Calculation frequency**: how often a title is produced, as **Every** *N* **messages**, counting the user's messages. The first message always gets a title, and a larger number means it's refreshed less often. A title someone typed by hand is never replaced.
4. Set **Number of messages to consider**: how many of the most recent messages the model reads when it writes the title.
5. Leave the **Title generation template prompt** as provided, or adjust it.

## Topic detection

Topic detection tags each conversation with up to three topics from a list you define, so you can filter conversations and see what people ask about most.

1. Turn on **Enable topic detection**.
2. Choose a **Topics detection model**.
3. Set the **Calculation frequency** and **Number of messages to consider**, exactly as in title generation.
4. Build your **Topic list**. These are the labels the model can choose from, for example *Order Status*, *Billing Request*, and *Tech Support*. Remove a topic with its **×**, and add a new one with **New**.
5. Leave the **Topic detection template prompt** as provided, or adjust it. It instructs the model to return only labels from your list, written exactly as they appear there.

## Sentiment analysis

Sentiment analysis estimates how the user feels during the conversation, surfaced as a sentiment badge alongside it.

1. Turn on **Enable sentiment analysis**.
2. Choose a **Sentiment analysis model**.
3. Set the **Calculation frequency** and **Number of messages to consider**.
4. Adjust the **Sentiment list** if you need to: each sentiment has a label and a color, which is how it appears in the Conversations list.

## Summary generation

Summary generation lets an administrator read a structured recap of a conversation before taking it over. Summaries always use these settings: touchpoints can't override them.

1. Turn on **Enable summary generation**.
2. Choose a **Summary generation model**. Thinking models are not recommended for this task.
3. Set **Number of messages to consider** (`0` means the whole conversation).

Each task's [prompt](/reference/glossary#prompt) field comes with a default, and **Restore default** brings it back. Change a prompt only if the results aren't what you want.

## Save your changes

Select **Save** to apply your choices, or **Cancel** to discard them. The tasks you turned on run on new messages from then on, with the model you picked or the default it follows.

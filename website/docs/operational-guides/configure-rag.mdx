# Configure Graph RAG

Graph RAG is the retrieval tool on a Knowledge's touchpoint. It finds the resources whose meaning matches a question, then follows the relations between them to pull in related resources a meaning-only search would miss. You tune it in three places: how files are chunked, whether chunks get keywords, and the settings of the Graph RAG tool itself.

## Prerequisites

- A Knowledge with **Allow AI search** turned on and an embedding model selected. See [Create a Knowledge](/operational-guides/create-knowledge#configure-ai-search).
- **Update** on the **Knowledge** row of your role, and **Update** on the **Touchpoints** row to tune the tool. See [Manage roles and users](/operational-guides/roles-and-users).

## Choose a chunking type

Chunking splits each file into smaller pieces before embedding, and search returns those pieces. Choose the type on the Knowledge's **AI Search** tab. The settings button next to **Chunking type** opens the options of the selected chunker, such as **Chunk size**.

| Type | Pick it when |
| :--- | :--- |
| **Recursive Chunker** | Your files are long and structured, such as manuals, policies, or reports with headings and paragraphs. It splits along that structure first, so a chunk tends to hold one section. |
| **Semantic Chunker** (default) | Topics change without clear headings, such as transcripts or meeting notes. It keeps sentences about the same topic together. |
| **Sentence Chunker** | Answers must quote whole sentences, such as FAQs or short articles. No sentence is cut in half. |
| **Token Chunker** | Every chunk must have the same size, regardless of the text's structure. |

Chunking, embedding, and keyword extraction run on text resources only.

## Add keywords to chunks (optional)

Keyword extraction tags each chunk with its most representative terms. Graph RAG uses them as an extra signal when it ranks results.

1. On the **AI Search** tab, turn on **Allow keywords extraction**.
2. Choose a **Keyword extraction method**:
   - **Word frequency (rule based)**: picks frequent words, with no AI requests. Supports English and Italian; Italian results may contain word stems.
   - **AI model (LLM)**: the default model of the Knowledge's touchpoint picks the terms, with one AI request per chunk. Better results, slower. You can add a **Custom extraction prompt (optional)**, for example to focus on product names.
3. Set **Maximum keywords per text chunk**, from 1 to 50.
4. Select **Save**.

Extraction runs when chunks are created during processing. Saving these settings doesn't update keywords already extracted.

## Tune the Graph RAG tool

Open the Knowledge's touchpoint in **Settings** → **Touchpoints**, open the Graph RAG tool, and edit its **Parameters**.

### Core settings

- **Knowledge Ids:** the Knowledges this tool searches. Left empty, the tool searches every Knowledge the user can access, up to a server limit.
- **Use Graph Expansion:** follows relations between resources. Default: on. Turn it off for a meaning-only search.
- **Category Filter** and **Tag Filter:** narrow the search to resources with these categories or tags. Leave them empty to search everything.

### Find matching resources

| Setting | What it does |
| :--- | :--- |
| **Initial Search Limit** | How many results to fetch before filtering. Leave it empty to let the server size it from **Max Rag Tokens**. A higher value widens the pool but adds latency. |
| **Semantic Threshold** (0.0 to 1.0, default 0.5) | Minimum similarity to keep a result. Lower it (0.3) for more results; raise it (0.7) for more precise ones. |

### Follow relations

| Setting | What it does |
| :--- | :--- |
| **Graph Expansion Threshold** (0.0 to 1.0, default 0.45) | Minimum score for a resource to have its relations followed, so weak matches don't pull in unrelated neighbors. |
| **Relationship Types** | Which relations to follow (for example "is part of", "references"). Leave empty to follow all. |
| **Max Graph Results** (minimum 1, default 10) | How many related resources to fetch per starting resource. |
| **Use Tags** and **Tags List** | Also follow resources that share tags (off by default). **Tags List** limits this to the tags you name. |

### Rank the results

Related resources are ranked by a mix of meaning and shared keywords. Only as much text as fits in **Max Rag Tokens** reaches the model.

| Setting | What it does |
| :--- | :--- |
| **Semantic Weight** / **Keyword Weight** (0.0 to 1.0, defaults 0.8 and 0.2) | Balance meaning against exact terms. Keep the two adding up to 1.0. |
| **Keyword Overlap Method** | How shared keywords are counted. The default, `fuzzy`, tolerates partial matches and typos. |
| **Relevance Threshold** (0.0 to 1.0, default 0.35) | Minimum final score for a related resource to be kept. |
| **Max Rag Tokens** (minimum 1, default 4000) | Maximum amount of retrieved text passed to the model. Leave room for the prompts and the answer. |

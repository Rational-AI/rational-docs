# Configure Graph RAG
 
Graph RAG is a retrieval tool you add to a Touchpoint. It searches your Knowledge for relevant resources, then follows the relationships between them to find more. This guide takes you from a new Knowledge to a working, tuned Graph RAG tool.
 

:::note[What is Graph RAG?]
A basic (naive) RAG search finds resources that match the meaning of a query. Graph RAG does that first, then traverses the knowledge graph to pull in related resources the meaning-only search would miss.
:::

## Prerequisites
 
Before you start, make sure you have:
 
- The Knowledge module in your license, **Create** and **Update** on the **Knowledge** row of your role, and **Update** on the **Touchpoints** row to tune the tool. See [Manage roles and users](/operational-guides/roles-and-users).
- An embedding model available in the **AI Model Registry**.
- Content (documents or other resources) ready to add to a Knowledge.
## How the setup works
 
Graph RAG comes together in three parts:
 
1. **Create a Knowledge:** the set of resources to search, plus the rules for how resources are processed.
2. **Configure its Touchpoint:** the model and instructions for answering questions.
3. **Tune the Graph RAG tool:** how broad and how strict the retrieval is.
You do the first two once. You return to the third whenever you want to adjust quality.
 
## Create a Knowledge
 
A Knowledge holds your resources and defines how they are processed when added. Creating one is the first step, because Graph RAG searches a Knowledge.
 
1. Go to **Settings** → **Knowledge**, select **New**, then **New knowledge**.
2. Replace **Untitled knowledge...** with a name, and add an optional description.
3. Open the **AI Search** tab to set up processing.

### Set up AI Search
 
The **AI Search** tab controls how resources are prepared for retrieval. Configure these in order:
 
1. Turn on **Allow AI search**. This enables the RAG process for the Knowledge.
2. Select an **Embedding model**. This model converts text into vectors so the system can measure how similar a resource is to a query. If AI search is on and no model is selected, the tab warns that the assistant cannot search this Knowledge until you pick one.
3. Choose a **Chunking type**. Chunking splits each resource into smaller pieces before embedding. The settings button next to **Chunking type** opens the options of the selected chunker. See [Chunking types reference](#chunking-types-reference).

:::note[Processing applies to text]
Chunking, embedding, and keyword extraction currently run on textual resources only.
:::

### Set up keyword extraction (optional)
 
Keyword extraction tags each chunk with its most representative terms. Graph RAG uses these terms as an extra signal when ranking results.
 
1. Turn on **Allow keywords extraction**.
2. Choose a **Keyword extraction method**:

| Method | How it works | When to use |
| :--- | :--- | :--- |
| **Word frequency (rule based)** | Selects frequent words, removes common words and groups similar word forms. Supports English and Italian; Italian results may contain word stems. No AI model or prompt is used. | Faster, no AI requests. |
| **AI model (LLM)** | The default AI model of the Knowledge's touchpoint picks the relevant words and phrases, with one AI request for each text chunk. | Better quality, slower. Needs a touchpoint with a default model. |

3. Set **Maximum keywords per text chunk**, from 1 to 50.

With **AI model (LLM)** you can enter a **Custom extraction prompt (optional)**, which helps when terms should be domain-specific. Leave it empty to use the default extraction instructions.

Extraction runs when text chunks are created during processing. Saving these settings does not update keywords already extracted.

## Configure the Touchpoint
 
Creating a Knowledge also creates a touchpoint named after it (*Knowledge name* - Touchpoint), with the read-only RAG tools, Graph RAG included, already pointed at the Knowledge. Adjust it in **Settings** → **Touchpoints**.
 
 {/* The Touchpoint editor open on the Models tab](path) * */}

- **Default model:** the model that writes the answers. Choose from the available models.
- **System prompt:** the instructions for that model. You can edit the default.

The default prompt tells the model to call the tool that describes the structure of the data first, then the tools that retrieve it, and to say it doesn't know when the tools don't find the answer.

 ## Tune the Graph RAG tool
 
The Graph RAG tool (`rag_query_graph`) runs in three phases. Each phase has settings that trade breadth against precision. To change them, open the tool in the touchpoint's tools and edit its **Parameters**.
 
### Core settings
 
- **Knowledge Ids:** the Knowledges this tool searches. Select one or more. Left empty, the tool searches every Knowledge the user can access, up to a server limit.
- **Use Graph Expansion:** the master switch for following relationships. Default: on. Off means a basic semantic search only.
- **Category Filter** and **Tag Filter:** category and tag names that narrow the search to matching resources. Leave them empty to search everything.
### Phase 1: Semantic search
 
The tool first finds resources that match the meaning of the query.
 
| Setting | What it does | Effect |
| :--- | :--- | :--- |
| **Initial Search Limit** | How many results to fetch before filtering. | Leave it empty (recommended) to let the server size it from **Max Rag Tokens**. A higher value widens the pool but adds latency. |
| **Semantic Threshold** (0.0 to 1.0, default 0.5) | Minimum similarity score to keep a result. | Lower (0.3) = more results; higher (0.7) = more precise. |
 
### Phase 2: Graph expansion
 
The tool takes the strongest Phase 1 results and follows their relationships to find related resources.
 
| Setting | What it does | Effect |
| :--- | :--- | :--- |
| **Graph Expansion Threshold** (0.0 to 1.0, default 0.45) | Minimum Phase 1 score for a resource to have its relationships explored. | Keeps low-relevance results from pulling in irrelevant neighbors. |
| **Relationship Types** | Which kinds of relationships to follow (for example "is part of", "references"). | Leave empty to follow all types. |
| **Max Graph Results** (minimum 1, default 10) | How many related resources to retrieve per starting resource. | Controls breadth and performance. |
| **Use Tags** and **Tags List** | Also follow resources that share tags (off by default). **Tags List** limits this to the tags you name. | Adds neighbors that have no explicit relationship. |
 
### Phase 3: Final ranking
 
The tool combines results from both phases, scores them, and keeps as much text as fits in **Max Rag Tokens**. Phase 2 resources get a hybrid score that blends meaning and keyword overlap.
 
The hybrid score is calculated as:
 
```text
combined_score = (semanticWeight * semantic_score) + (keywordWeight * keyword_overlap_score)
```
 
| Setting | What it does | Effect |
| :--- | :--- | :--- |
| **Semantic Weight** / **Keyword Weight** (0.0 to 1.0 each, defaults 0.8 and 0.2) | Balances meaning against exact-term overlap. Keep them adding up to 1.0. | High Semantic Weight (0.8) favors topic; high Keyword Weight (0.8) favors matching terms. |
| **Keyword Overlap Method** | The algorithm for scoring term overlap. | `fuzzy` is the default (handles partial matches and typos). `jaccard`, `dice`, `cosine`, and `overlap_ratio` are also available. |
| **Relevance Threshold** (0.0 to 1.0, default 0.35) | Final filter for Phase 2 resources. | Only resources at or above this score are kept. |
| **Max Rag Tokens** (minimum 1, default 4000) | Maximum number of tokens of retrieved text passed to the model. | Leave room for the prompts and the model's answer. |
 
## Chunking types reference
 
Chunking splits a resource into smaller pieces before embedding. Choose the type when you set up AI Search.
 
| Type | How it splits | Notes |
| :--- | :--- | :--- |
| **Recursive Chunker** | Recursively chunks documents into smaller chunks. | Best for long documents with a well-defined structure. Selected by default. |
| **Semantic Chunker** | Groups content based on semantic similarity. | Best for preserving context and topical coherence. |
| **Sentence Chunker** | Splits text at sentence boundaries. | No sentence is cut in half. |
| **Token Chunker** | Splits text into chunks of a fixed token count. | Use it when chunk size must be predictable. |

# Configure a connector

Connectors are how Rational AI talks to the outside world. This guide shows you what a connector is, how to add one, and how to check what it powers before you change it.

:::note[What is a connector?]
A connector links Rational AI to an external provider so the platform can use that provider's models, data sources, or tools. For example, a connector to OpenAI or Anthropic is what lets you use their [language models](/concepts/LLMs) inside Rational AI.
:::

You will find connectors at **Settings** → **Connectors**.

## What a connector is

A connector is a saved, reusable link to one external provider. Once configured, it can back several things at once: an AI model, a data source, or a tool. That is why connectors live in their own area instead of being set up over and over inside each feature.

The **Connectors** page lists everything you have configured on the left, such as **Rational Connector** and **OpenRouter**. Select one to see what it does:

- A short **description** of the connector.
- Its **Provider** (the external service it links to).
- A **Used N times** counter, so you can see how active it is.
- How many **AI Models**, **Sources**, and **Tools** it currently backs.

## Add a connector

1. Go to **Settings** → **Connectors** and select **Add**. This opens **Add a new connector**.
2. Choose a **provider** from the gallery. Each option has a one-line description to help you pick (see [Available providers](#available-providers)).
3. Supply the provider's **credentials**. This is usually an API key you get from the provider's own dashboard. Paste your own key into the connector's field; never reuse someone else's. Keys are stored by the platform and are not shared.
4. Select **Save**.

## Available providers

| Provider | What it connects | What you supply |
|----------|------------------|-----------------|
| **Google** | A Google account, for Drive, Gmail and Calendar. | OAuth client ID and secret, then sign in. |
| **AWS** | An AWS account, for Amazon S3 sources. | Access key ID and secret access key. |
| **OpenAI** | OpenAI models. | API key. |
| **Anthropic** | Anthropic's Claude models. | API key. |
| **OpenRouter** | Models from many providers through one key. | API key. |
| **Xference** | Hosted OpenAI-compatible models from Xference. | API key. |
| **MiniMax** | Hosted OpenAI-compatible models from MiniMax. | API key. |
| **OpenAI Compatible** | Any API that follows the OpenAI format: self-hosted models, proxies, other providers. | Base URL and API key. |
| **System One Compatible** | A Jev or System One compatible decision API. | Base URL ending in `/v1`, and an API key if the provider requires one. |
| **Google Vertex AI** | Gemini models on Vertex AI, pinned to one Google Cloud region. | Project ID and location. No key. |
| **Brave Search** | Web, news, image, video and local search. | API key. |
| **Google Service Account Key** | Google Cloud services such as Storage and BigQuery. | Service account key. |
| **Azure** | An Azure account, for Azure Blob Storage sources. | Client credentials. |
| **Microsoft OneDrive** | OneDrive and SharePoint files, for OneDrive sources. | Client ID and secret, with user sign-in or application permissions. |
| **LinkedIn**, **Instagram**, **Facebook** | A company page or business account to publish Social studio posts to. | Your own app's ID and secret, then sign in. |
| **Git credentials** | Private Git repositories, for Git sources. | Host and an HTTPS token. Public repositories need no connector. |
| **RabbitMQ** | A message broker whose queues announce files to process. | Host, user and password. |
| **Microsoft SQL Server** | A SQL Server database that extensions read. | Host, database, and a read-only login. |

The providers below need more than a key. Their steps follow.

### Connect Gemini models on Vertex AI

Use **Google Vertex AI** when your Gemini traffic must stay in one Google Cloud region, for example for data residency. The connector stores no credential: Rational AI calls Vertex AI as its own Google Cloud identity.

1. In Google Cloud, grant the platform's Google Cloud identity the **Vertex AI User** role on your project.
2. In **Add a new connector**, choose **Google Vertex AI**.
3. Enter the **Project ID** (for example `my-project-123`) and the **Location**: a single region such as `europe-west8`.
4. Select **Add**, then add the models you need in the [AI Model Registry](/operational-guides/ai-model-registry-features). The list offers the Gemini chat models served in that region.

:::note[One region, never global]
**Location** refuses `global` and multi-regions such as `eu` or `us`: pinning a single region is what the connector is for. Only chat completions are sent to Vertex AI.
:::

### Connect a System One compatible decision API

Use **System One Compatible** to reach a decision API that follows the System One protocol, such as Jev.

1. In **Add a new connector**, choose **System One Compatible**.
2. Enter the provider's **Base URL**, ending in `/v1`.
3. Enter an **API Key** if the provider requires one; otherwise leave it empty.
4. Select **Add**.

The provider must support System One evaluation and model listing.

### Connect a Microsoft SQL Server database

Use **Microsoft SQL Server** to let extensions give models read-only access to a database's tables, for example with the **SQL Server** extension, which lists tables, describes them, and runs a single `SELECT`.

1. In **Add a new connector**, choose **Microsoft SQL Server**.
2. Enter the **Host** (a name or IP address, such as `sql01.example.local`), and the **Database**.
3. Leave **Port** empty for the default `1433`, and **Instance** empty for the default instance; otherwise enter them (for example `SQLEXPRESS`).
4. Enter the **Username** and **Password** of a SQL Server login with read-only permissions on the database.
5. Turn on **Encrypt the connection** to require encryption for the whole session.
6. Select **Add**.

:::warning[Use a login that can only read]
The extension refuses anything but a single `SELECT`, but that is a text check, not a guarantee. The login's permissions are the real protection: give it the `db_datareader` role, or `SELECT` on the schemas it needs, and no access to linked servers.
:::

:::note[Encryption doesn't verify the server]
With **Encrypt the connection** on, traffic is encrypted, but the server certificate is not verified: encryption protects against eavesdropping, not against a server pretending to be yours. With it off, encryption is still requested for the login.
:::

If you build your own extension, request this connector in its manifest with the connector type `sqlServer`.

### Connect a RabbitMQ broker

Use **RabbitMQ** when another system announces documents to process on a queue. The connector holds the broker; a [RabbitMQ queue source](/operational-guides/configure-sources#process-files-announced-on-a-rabbitmq-queue) picks the queue.

1. In **Add a new connector**, choose **RabbitMQ**.
2. Enter the **Host** (for example `rabbitmq.example.com`) and, if not the default, the **Port** (`5672`, or `5671` with TLS). Turn on **Use TLS** if the broker requires it.
3. Enter the **Virtual host** (default `/`), and the **Username** and **Password** that the broker's owner created for Rational AI.
4. *(Optional)* Enter a **File download token**: it is sent as a Bearer token when downloading the files the messages point to.
5. Select **Add**.

:::note[Port and TLS are set once]
After creation you can edit the host, virtual host, username, password, and token, but not the port or TLS. To change those, create a new connector.
:::

### Connect a social account for publishing

The **LinkedIn**, **Instagram**, and **Facebook** connectors let Social studio publish posts through your own developer app.

1. Create the app on the provider's developer portal, as the dialog describes: a LinkedIn app with the Community Management API for a company page, or a Meta Business app with Instagram login or Facebook Login for Business.
2. In **Add a new connector**, choose the network and copy the **Redirect URL to add to the app** into your app's settings.
3. Enter a **Name**, and your app's ID and secret. For Facebook, also enter the configuration ID if you created one.
4. Select **Add and authorize** and sign in with an account that administers the page or account you want to publish to.

## See what a connector powers

Connectors rarely sit on their own. Before you edit or remove one, check what depends on it, so you don't break a model or a data source that's in use.

Select a connector in the list and look at its **AI Models**, **Sources**, and **Tools** counts. These tell you exactly where the connector is wired in:

- **AI Models** — a connector is what a model proxy points to. When you add a third-party model in the [AI Model Registry](/operational-guides/ai-model-registry-features) using **Add a proxy to a third-party model**, you select the connector that reaches the provider.
- **Sources** — some [Sources](/operational-guides/configure-sources) use a connector to reach the external system that holds your data.
- **Tools** — some tools (such as a web search tool backed by Brave Search) rely on a connector for access.

The **Used N times** counter is a quick health check: a connector showing zero uses is safe to remove, while a heavily used one should be changed with care.

## Result

You have a connector configured and linked to an external provider, and you know how to see what it powers. You can now point an AI model, a Source, or a tool at it. A common next step is to add a third-party model in the [AI Model Registry](/operational-guides/ai-model-registry-features) that uses your new connector.

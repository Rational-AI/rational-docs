# Configure connectors

A connector stores the credentials Rational AI uses to reach an external service, such as an API key, a database login or an OAuth sign-in. You set it up once in **Settings** → **Connectors**, and every [AI model](/operational-guides/ai-model-registry-features), [source](/operational-guides/configure-sources) and tool that needs that service uses it. Rotating a key in the connector updates all of them.

Adding a connector needs **Create** on the **Connectors** row of your role, editing it needs **Update**, and deleting it needs **Delete**. No license module is required. See [Manage roles and users](/operational-guides/roles-and-users).

## Add a connector

Each provider has its own page with what to prepare on the external service and the fields to fill in. The steps in Rational AI are the same for all of them:

1. Go to **Settings** → **Connectors** and select **Add**. With no connectors yet, the button reads **Add new**.
2. Under **Browse connectors**, select the provider, then select **Add**. See [Available providers](#available-providers).
3. Enter a **Name**, an optional **Description**, and the credentials the provider asks for.
4. Select **Add**. For providers that sign in with OAuth (Google, Microsoft OneDrive with user sign-in, LinkedIn, Instagram, and Facebook), the button reads **Add and authorize** and opens the provider's sign-in.

A connector on its own does nothing. Afterward, use it where it belongs: add models in the AI Model Registry, add a source, select it in an extension's configuration, or publish from Social studio. Each provider page ends with that step.

## Edit a connector

1. Go to **Settings** → **Connectors** and select the connector.
2. Change its name, its description, or the fields under **Configuration**.
3. Select **Save**, or **Undo** to discard your changes.

Secret fields, such as keys, secrets, passwords and tokens, are never shown. Leave one blank to keep the stored value, or enter a new value to replace it.

A few settings are fixed when the connector is created: the authentication mode of a Microsoft OneDrive connector, the port and TLS of a RabbitMQ connector, the port of a Microsoft SQL Server connector, and the engine, port and file path of a SQL database connector. To change them, create a new connector and move what uses the old one.

When a connector that signs in with OAuth still needs its sign-in, it shows **Missing authentication**. Open the options menu (the three vertical dots) and select **Complete authentication**.

## See what a connector powers

Select a connector to see what depends on it before you change or delete it. **Used N times** adds up three counts:

- **AI Models**: models added from the connector in the [AI Model Registry](/operational-guides/ai-model-registry-features).
- **Sources**: [sources](/operational-guides/configure-sources) that sync through the connector.
- **Tools**: tools of installed [extensions](/operational-guides/manage-extensions) whose configuration selects the connector.

The connector's **Provider pricing and subscriptions** section lists the plans you track for it with **Add plan**. Plans aren't part of the counts, but they do keep a connector from being deleted.

## Delete a connector

1. Select the connector, open the options menu (the three vertical dots), and select **Delete**.
2. Confirm with **Delete connector**.

Deleting is refused while models, sources, provider plans or extension configurations still use the connector, and built-in connectors can't be deleted. Remove or move those first. A deleted connector can't be restored.

# Create a Knowledge

A Knowledge holds your organization's information: the files your AI searches when it answers, and the records your team keeps up to date. Follow these steps to go from an empty Knowledge to one you can chat with.

## Prerequisites

- **The Knowledge module in your license.** Without it, **Knowledge** doesn't appear in the navigation or in **Settings**. See [License and activation](/operational-guides/license).
- **Create** on the **Knowledge** row of your role, plus **Update** to configure it. See [Manage roles and users](/operational-guides/roles-and-users).
- **AI models in the AI Model Registry:** a **Text Generation** model for the Knowledge's chat, and an **Embedding** model if you turn on **Allow AI search**. See **Settings** → **AI Model Registry**.

## Add a Knowledge

1. Open the **Knowledge** tab and select **New** → **New knowledge**. Rational AI creates the Knowledge with a default name and opens its settings.
2. Replace the default with a clear name, for example `Data Marketing 2026`.
3. Add a description of the content and purpose. It appears on one line under the name on the Knowledge's card.

## Configure AI Search

The **AI Search** tab controls how files are prepared so the AI can search them.

1. Turn on **Allow AI search**.
2. Select an **Embedding model**. It turns each piece of text into numbers so Rational AI can measure how close it is to a question.
3. Choose a **Chunking type**, which decides how each file is split into smaller pieces before embedding. **Recursive Chunker** is selected by default. To pick another, see [Choose a chunking type](/operational-guides/configure-rag#choose-a-chunking-type).
4. Select **Save**.

## Choose how files are processed

Every file added to a Knowledge runs through a pipeline before the AI can search it. The **Sources** tab sets which one, so uploads, source syncs, and API requests all treat files the same way.

1. In the Knowledge's settings, select the **Sources** tab.
2. In **Default workflow**, pick the pipeline:
   - **Classic pipeline** (the default): each file is routed by the **Default processing rule**.
   - A workflow: every file added to this Knowledge runs through it.
3. In **Default processing rule**, pick the rule that maps each file type to its processing step.
4. Select **Save**.

The reprocess dialog can still force a different pipeline for a single run.

## Set up the Knowledge's touchpoint

Creating a Knowledge also creates a touchpoint named after it (*Knowledge name* - Touchpoint), with the read-only RAG tools, Graph RAG included, already pointed at this Knowledge. Customize it in **Settings** → **Touchpoints**:

- **Default model:** the model that writes the answers.
- **System prompt:** the instructions for that model.

The default prompt tells the model to call the tool that describes the structure of the data first, then the tools that retrieve it, and to say it doesn't know when the tools don't find the answer.

## Start a chat with your Knowledge

You can open a chat on the Knowledge before it has any content and add data as you go.

1. Open the **Knowledge** tab and select the card of the Knowledge you created.
2. In the chat panel at the side, select **New chat** (the **+** icon when the panel is collapsed).

The chat runs on the Knowledge's touchpoint.

## Add content

A new Knowledge is empty. Fill it in any of these ways:

- **Upload files:** select **Add file** in the Knowledge's **Options** menu. See [Add and manage content](/operational-guides/manage-knowledge-resources#upload-files).
- **Sync a source:** connect a folder or service and keep it in sync. See [Connect Google Drive](/operational-guides/integrate-data).
- **Import a spreadsheet as records:** see [Import records from Excel or CSV](/operational-guides/import-knowledge).

# Create a Knowledge base
 
A Knowledge is a workspace for your organization's information: the resources your AI searches when answering questions, and the records your team keeps up to date. This guide takes you from an empty Knowledge to a configured one you can chat with.
 

:::note[What is a Knowledge?]
A Knowledge holds your resources (documents, FAQs, manuals) and the rules for processing them, which Rational AI's RAG system searches to ground its answers in your own data. It can also hold records grouped into collections, with attributes, reminders, saved and custom views, an embed widget for your website, and its own chat.
:::

## Prerequisites
 
Before you start, make sure you have:
 
- **The Knowledge module in your license:** without it, **Knowledge** doesn't appear in the navigation or in **Settings**. See [License and activation](/operational-guides/license).
- **Permission to create a Knowledge:** **Create** on the **Knowledge** row of your role, plus **Update** to configure it. See [Manage roles and users](/operational-guides/roles-and-users).
- **A list of your data sources:** the documents, FAQs, or manuals that will feed the Knowledge (see **Settings** → **Sources**).
- **The required extensions installed:**
  - **Time Server:** needed for time-based searches (filtering by date or temporal relevance).
  - **Rational Knowledge - RAG Query Server:** enables advanced queries and the RAG model on the Knowledge.
- **AI models configured:** a **Text Generation** model for the Knowledge's chat, and an **Embedding** model if you turn on **Allow AI search**, both active in the **AI Model Registry** (see **Settings** → **AI Model Registry**).
## Add a Knowledge
 
1. Open the **Knowledge** tab and select **New** → **New knowledge**. Rational AI creates the Knowledge with a default name and opens its settings.
2. Replace the default with a clear **name** (for example `Data Marketing 2026 KB`).
3. Add a **description** of the content and purpose. This helps your team maintain it later: the description is shown on the Knowledge's card in the **Knowledge** tab, on one line under the name.

## Configure AI Search
 
The **AI Search** tab controls how resources are prepared for retrieval. Configure these in order:
 
1. Turn on **Allow AI search**. This enables the RAG process for the Knowledge.
2. Select an **Embedding model**. This model converts text into vectors so the system can measure how similar a resource is to a query.
3. Choose a **Chunking type**. Chunking splits each resource into smaller pieces before embedding. **Recursive Chunker** is selected by default. See [Chunking types reference](/operational-guides/configure-rag#chunking-types-reference).
4. Select **Save**.

:::note[Embedding works on chunks]
Embedding runs on the small chunks of a resource, not the whole text. The resulting vectors are what RAG compares against a user's question.
:::

## Choose how files are processed

Every file added to a Knowledge runs through a pipeline before the AI can search it. The **Sources** tab sets which one, so uploads, source syncs, and API requests all treat the files the same way.

1. In the Knowledge's settings, select the **Sources** tab.
2. In **Default workflow**, pick the pipeline:
   - **Classic pipeline** (the default): each file is routed by the **Default processing rule** below.
   - A [workflow](/operational-guides/create-workflow#make-a-workflow-the-default-for-a-knowledge): every file added to this Knowledge runs through it.
3. In **Default processing rule**, pick the rule that maps each file type to its processing step.
4. Select **Save**.

:::note[The default applies to every trigger]
The default workflow is used whenever a run doesn't ask for a specific one: a file uploaded in the Control Room, a source that finishes syncing, or an API client that reprocesses the Knowledge without naming a workflow. The reprocess dialog can still force a different pipeline for a single run.
:::

## Default Touchpoint
 
Creating a Knowledge also creates a touchpoint named after it (*Knowledge name* - Touchpoint), with the read-only RAG tools, Graph RAG included, already pointed at this Knowledge. Customize it in **Settings** → **Touchpoints**, where you can set the **Default model** and the **System prompt** for this Knowledge.

By default, the prompt tells the model to:

1. **Analyze the data structure:** call the tool that describes the structure of the data first.
2. **Retrieve the data:** use the tools that fit the question to fetch the information.
3. **Say when it doesn't know:** answer from the tools only, and say so when they don't find the answer.

To tune how Graph RAG retrieves, see [Configure Graph RAG](/operational-guides/configure-rag).
 
## Start a chat with your Knowledge
 
Your Knowledge is created but still empty. You can open a chat against it now and add data as you go.
 
1. Open the **Knowledge** tab from the main navigation.
2. Select the **card** for the Knowledge you created. This opens its management view.
3. In the chat panel at the side, select **New chat** (the **+** icon when the panel is collapsed).
4. The chat opens on the Knowledge's touchpoint, ready for queries.

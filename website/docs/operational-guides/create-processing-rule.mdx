# Create a processing rule
This guide explains how to create, configure, and manage processing rules in the AI Control Room. 


:::note[Glossary]
What is a **processing rule**?  
A processing rule is a Python script that picks which step processes each file, based on document type, content, source or any custom rule. It routes files and doesn't transform them: the step it picks does the work.
A Knowledge uses its processing rule when its **Default workflow** is the **Classic pipeline**. Set the **Default processing rule** on the Knowledge's **Sources** tab, and override it for one attached source if needed.
:::

To manage processing rules, open the **Settings** area and navigate to **Workflows** from the left sidebar. 
Then switch to the **Processing rules** tab.

### Rules list
The list shows all processing rules that have been created, by name, with a search box. Processing rules have no enable switch: a rule runs when a Knowledge or one of its sources uses it.

### Rule editor
When you select a rule, its editor opens.

The editor includes:
* The rule name.
* The rule's Python code.
* **Save** and **Undo** for your changes.
* A **⋮** menu with **Open in Lab**, **Download** (the `.py` file), **Export (JSON)** and **Delete**. Deleting a rule keeps the workflow runs that used it.

## Creating your first processing rule
If you're a new user, the page shows *"No processing rules"*. Create your first rule in a few steps:
* Select **New** (or **Add new** on the empty page), then **From scratch**. **Import JSON** loads a rule exported elsewhere.
* Replace *Untitled processing rule* with a clear and descriptive **name**: for example `MyProcessingRule`.
* Define the **rule logic** in the code editor.
* Select **Save**.

To put the rule to work, select it as the **Default processing rule** on a Knowledge's **Sources** tab, or as the **Processing rule** in a source's **Data processing settings**.

## Processing rule logic

A processing rule allows to devise which workflow to apply to the Knowledge documents.
Being code, you can develop arbitrarily complex conditions to decide which workflow applies to your document, for example:

```python
#!/usr/bin/env -S uv run --script
# /// script
# requires-python = ">=3.12,<3.13"
# dependencies = [
#     "rational-client",
# ]
# ///

from rational_client.core import File
from rational_client.utils import run


def router(resource: File, options: dict):
    """Routes the resource to the correct workflow based on file extension."""
    filename = resource.name
    if not filename:
        return None

    # Main switch
    if filename == "orders.json":
        workflow = "Workflow Orders"
    elif filename == "products.json":
        workflow = "Workflow Products"
    elif filename == "orgchart.json":
        workflow = "Workflow Orgchart"
    elif filename == "stores.json":
        workflow = "Workflow Stores"
    elif filename.endswith(".pdf"):
        workflow = "Workflow PDF"
    elif filename.endswith(".doc") or filename.endswith(".docx"):
        workflow = "Workflow Docling"
    elif filename.endswith(".urls"):
        workflow = "Workflow Urls"
    else:
        workflow = None

    return workflow

run(router)
```

As for the workflows, the entrypoint is the `run` function which triggers the processing rule business logic, the `router` function.
Basically, here we decide the workflow to apply, based on some characteristics of the Knowledge document, for example, its filename.

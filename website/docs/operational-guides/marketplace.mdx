# Install solutions from the Marketplace

The **Marketplace** offers ready-made solutions for common jobs, such as a CRM, a due diligence data room or an AI Act register. You pick one, choose where its content goes, and Rational AI sets it up in one step. Later you can update it, go back to an earlier version or remove it, without losing the records you added.

:::note[What is a solution?]
A **solution** is an [extension](/operational-guides/manage-extensions) published by Rational AI that sets up a complete use case. Depending on the solution, installing it creates a Knowledge with its collections, attributes and saved views, example records, reminders, processing workflows, tools and skills for the assistant, BI dashboards, a website widget or a data source that syncs on a schedule. Some solutions also install automated agents. Every solution is listed with what it installs before you install it.
:::

## Prerequisites

- **A signed-in account:** everyone can browse the Marketplace and read the solution pages.
- **Permission to install extensions:** installing needs **Create** on the **Extensions** row of your role. Without it, you see **Ask an admin** instead of **Install** (see [Ask the admins to install a solution](#ask-the-admins-to-install-a-solution)).
- **Permission to update the target Knowledge:** only if you install a solution into a Knowledge that already exists. Your role needs **Update** on it in the **Knowledge** row.

## Find a solution

1. Select **Marketplace** in the top navigation.
2. Narrow the list in one of these ways:
   - Type in the search box. The search covers names, taglines, descriptions, industries, use cases and features.
   - Select a tile under **Browse by use case**.
   - Use the side panel: **All solutions**, **New and updated** (published or updated in the last 30 days), **Installed**, or a value under **By industry**, **By use case** or **Includes**.
3. Sort the results with **Newest**, **Recently updated**, **Name A to Z** or **Installed first**. To start over, select **Clear all**.

The filters list only the values that some solution has, each with its count:

| Filter | Values |
|--------|--------|
| **By industry** | Manufacturing, Public sector, Retail and fashion, Culture and archives, Defence and intelligence, Energy and utilities, Healthcare, Finance and insurance, Professional services |
| **By use case** | Compliance, Document processing, Supply chain, Sales and prospecting, Customer service, Human resources, Business intelligence, Contracts and suppliers, Product development, Production planning, Asset monitoring, Grants and funding, Public tenders, Marketing and social media, and more |
| **Includes** | Interactive views, BI dashboards, Workflows, Skills, Website widget, Agents and reminders |

When Rational AI features a solution, it appears at the top of the page with a **See the solution** link.

Each card shows the solution's name, tagline and what it brings (for example *"8 views · 3 agents"*), and a state when it is already in your workspace: **Installed**, **Update available**, **Setup 2 of 5** or **Installing**. The catalog is shown in your interface language when the solution is translated.

## Read the solution page

Select a card to open its page. Before you install, it tells you exactly what you get:

- **Views:** screenshots of the solution's saved views. Select **Preview views** to jump to them.
- **Overview:** how the solution works step by step, the collections it creates and questions you can ask the assistant.
- **What it installs:** the Knowledge, the agents with what triggers them, reminders, workflows, tools, BI dashboards and the website widget.
- **Permissions:** what the solution's agents or assistant may change, for example *"The assistant can change records in Opportunities."*, and which external source it reads from.
- **Setup after install:** the steps that become your checklist once the solution is installed.
- **Versions:** every published version with its date and release notes.

## Install a solution

1. On the solution's card or page, select **Install**. To install an older release, open the chevron next to **Install** and select **Install another version**.
2. In **Knowledge**, choose where the solution's content goes:
   - **+ New knowledge** creates a new Knowledge. Enter its **Knowledge name**; if the name is taken, the dialog suggests a free one.
   - An existing Knowledge adds the solution to it.
3. Set the options:

   | Option | When to use it |
   |--------|----------------|
   | **Content language** | Choose **Italiano** or **English** for the collections, views, agents and examples. It is offered only when the solution is translated, and updates keep the language you chose. |
   | **Include example data** | Leave it on to get records tagged *example*, so every view has something to show while you try the solution. Turn it off to start empty. |
   | **Start the agents after setup** | Shown only for solutions with agents. Off, the agents are created paused. |
   | **Send e-mail from** | Shown only when an agent can send e-mail: the mailbox it sends from. The default, *"None, the agents only draft"*, sends nothing. |
   | **Owner of examples and reminders** | The person who owns the example records and receives their reminders. It defaults to you; you can reassign records in bulk later. |

4. Check **This solution will be able to**, which lists what the solution may change or read.
5. Select **Install solution**. If one of its tools needs settings, such as an API key, select **Continue** and fill in the **Settings** form first.

The dialog shows each step as it runs. You can close it: the install goes on, and the card shows how far it is. When it finishes, select **Open** to go to the Knowledge.

:::note[An existing Knowledge keeps its content]
When you install into an existing Knowledge, its documents, records, attributes and name stay. The solution adds its collections, views, reminders and agents, and its processing rule and assistant instructions replace the ones the Knowledge had.
:::

If the install fails, everything it had created is undone, so you can select **Try again** without cleaning up first. A solution that reads from an external source also offers **Install without source**, for when the source is what fails.


## Ask the admins to install a solution

If you can't install extensions, ask the people who can:

1. On the solution's card or page, select **Ask an admin**.
2. Optionally, write in **Message (optional)** what you would use the solution for.
3. Select **Send request**.

Every administrator gets an in-app notification with your name, your message and a link to the solution page. You can ask once a day for each solution; a second request on the same day is answered with *"You already asked for this solution today"*.

## Follow the setup and status of a solution

Open an installed solution from the **Installed** filter or from its card. Its page becomes the solution's status page:

- **Setup:** the checklist from **Setup after install**, with the steps done so far. Select **Continue setup** to work through it. Ticks are saved with the installed solution.
- **Components:** the solution's sources, agents, reminders and views, each with its state, for example **Active**, **Sync failed**, **Last run failed**, **Paused** or **Needs owners** (records nobody is notified for). Each problem comes with its action (**Retry**, **View log**, **Resume** or **Assign**). A view you deleted shows as **Removed**, and an update doesn't bring it back.
- **Overview** and **Versions:** the same content as before the install.

The **More actions** menu has **Check for updates**, **Version history**, **Restart setup**, which marks every setup step as not done without touching any data, **Pause all agents** and **Uninstall…**. To open the solution's content, select **Open** followed by the Knowledge name.

## Update a solution

When a new version is published, the page shows *"Version … is available"*. Updates never touch your own records.

1. Select **Review update**. The dialog lists the release notes and every component the update adds, changes or removes: views, collections, reminders, agents, tools and dashboards.
2. Check **You changed N components**: for each component you edited yourself, the update keeps your version.
3. If you changed a collection and the update adds columns to it, each such collection has a checkbox, selected by default. Clear it to keep that collection as it is, without the new columns.
4. Select **Update solution**.

:::note[An update keeps the content language]
A solution stays in the language you installed it in. If a new version isn't available in that language, the dialog says so and the update can't be applied.
:::

How compatible updates are detected for the extension behind a solution, and what an update does to tools and touchpoints, is described in [Update and roll back extensions](/operational-guides/extension-updates).

## Restore an older version

If a new version doesn't suit you, go back:

1. Open the **Versions** tab and select **Restore this version** on the version you want.
2. Read the dialog: what the installed version added and the older one doesn't have is removed from the solution. Your records are not touched, and the components you changed keep your version.
3. Select **Restore version**.

## Uninstall a solution

1. In **More actions**, select **Uninstall…**.
2. Read which of the solution's agents and reminders the dialog says are removed, then choose what happens to the content:

   | Option | When to use it |
   |--------|----------------|
   | **Keep the knowledge and its records** *(default)* | You want to keep working with the data. The Knowledge stays with its views and records. |
   | **Delete the knowledge too** | You no longer need the data. The dialog tells you how many records will be deleted, examples and your own. Type the Knowledge name to confirm. |

3. Select **Uninstall solution**, or **Uninstall and delete**.

:::warning[Deleting the Knowledge cannot be undone]
**Delete the knowledge too** deletes the records and documents of the Knowledges the install created. A Knowledge that existed before you installed the solution into it is never deleted: it is kept and detached from the solution.
:::

A kept Knowledge is detached from the solution. If you install the same solution again later, it adopts that Knowledge again.

## What's in the catalog

Solutions cover compliance registers, document processing, sales and customer service, purchasing and supply chain, production and maintenance, quality, human resources, and finance. Examples include **CRM**, **Due diligence data room**, **AI Act register**, **NIS2 compliance**, **Public tenders**, **Plant maintenance** and **Privacy and GDPR**.

Rational AI publishes new solutions over time, so the Marketplace in your Control Room is the current list. Each solution's page says what it installs.

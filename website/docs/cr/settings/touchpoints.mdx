# Touchpoints

A touchpoint is a configured assistant that people talk to, for example one that answers questions about a specific product or handles a customer-care flow. Each touchpoint binds together a channel, a model and system prompt, the knowledge sources it can draw on, the tools and skills it can use, and its memory. Use this section to create touchpoints and tailor each one to a specific use case.

Touchpoints are not the agents of the [Agents](../Agents.mdx) section, which carry out jobs in runs on their own computer.

## Browse touchpoints

The Touchpoints page lists every touchpoint as a card. Each card shows its name, the channel it uses (for example, *Rational AI Chat*), and how many sources and tools it has. With **Update** on **Touchpoints**, the card also has a switch to enable or disable it. Use the search field to filter the list, and select a card to open its details.

## Create a touchpoint

Select **New**. A touchpoint named *New touchpoint* is created on your first [channel](/operational-guides/manage-channels), enabled, and opened so you can configure it through the tabs described in [Configure a touchpoint](#configure-a-touchpoint). **New** is unavailable until at least one channel exists. The new touchpoint gets the platform's default conversational model. Select **Save** to keep your changes, or **Undo** to discard them.

The **Default touchpoint** button at the top of the list opens the workspace assistant used by the main [Chat](../Chats.mdx), so you can [change its prompt](/operational-guides/configure-touchpoints#change-the-workspace-assistants-prompt).

## Configure a touchpoint

The details panel is organized into seven tabs:

### Settings

* **Touchpoint ID**: the unique identifier of the touchpoint (use the copy icon to copy it, for example when integrating an external client).
* **Channel**: the channel the touchpoint is exposed through.
* **API access**: on touchpoints using the **API** channel, the base URL and the touchpoint's own [API key](/operational-guides/api-access#give-an-application-its-own-touchpoint-key), with **Generate key**, **Rotate**, and **Revoke**.
* **Allow anonymous access**: lets people start a conversation without signing in. Off by default.
* **Canvas mode**, **Edit messages**, **Attachments** and **Regenerate response**: let users open the Canvas, edit a sent message, attach files, and regenerate an answer. All four are on by default.

### Models

* **System prompt**: the instructions that define the assistant's role and behavior for this touchpoint, with **Show unsaved changes** and **Expand editor** buttons. On the default touchpoint, **Restore default** brings back Rational AI's own instructions.
* **Default model** and the models table: the model that powers the touchpoint's responses, and the other models it may use.
* **Open advanced settings**: **Generation limits** (**Maximum output tokens**, **Stop generation on repetitive output**, the default **Reasoning** level and whether users may change it per conversation; see [Tune answer generation](/operational-guides/touchpoint-generation)), then **Title generation model**, **Sentiment analysis**, and **Topics detection**. Each of these three follows the platform defaults from [Conversations settings](conversations.mdx) until you switch off its **Use default …** option.
* **Response verification**: lets users check an answer against the retrieved knowledge.
* **Suggested questions**: example questions offered to people starting a chat, shown when **Enable example questions?** is on.

### Sources

Choose which [knowledge sources](sources.mdx) the touchpoint can draw on when answering, so the assistant only uses the relevant data for its use case. **Can change records** lets the assistant also [create and update records](/operational-guides/configure-touchpoints#let-the-assistant-change-a-knowledge) in a knowledge. On the default touchpoint the tab shows **All accessible knowledge bases** instead: each user automatically gets every enabled knowledge base they can read.

### Tools

Enable the [tools](extensions.mdx) the assistant is allowed to call during a conversation, choose **When to ask for confirmation**, and set **How long a tool may take**. Only administrators can add, edit or remove a touchpoint's tools or mark them **Sensitive**.

### Skills

Add the [skills](/operational-guides/agent-skills) the assistant can use, which users can also pick with `/` in the chat.

### Memory

Switch on **Personal memory** and **Shared memory**, curate shared memories, and choose what happens with **Long conversations**. See [Memory and long chats](/operational-guides/touchpoint-memory).

### Test runs

Replay past conversations against a change before it goes live. See [Test a touchpoint change](/operational-guides/test-touchpoint-changes).

## Manage a touchpoint

Use the switch on each card to enable or disable a touchpoint, or open the options menu (the three vertical dots) next to the touchpoint's name. Each action needs the matching permission on **Touchpoints**: **Update** to disable or enable, **Create** to duplicate, **Delete** to delete.

| Action | Description |
|--------|-------------|
| **Disable** / **Enable** | Take the touchpoint out of service without deleting it, or put it back. |
| **Duplicate** | Create a disabled copy of the touchpoint, with its tools and skills, named after it with *(copy)* at the end. |
| **Delete** | Permanently remove the touchpoint with its tool and skill settings and its memory. Its conversations are kept. A Knowledge or BI project whose touchpoint you delete gets a new touchpoint with default settings. The default touchpoint has no **Delete**. |

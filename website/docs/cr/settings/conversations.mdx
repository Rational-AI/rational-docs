# Conversations

The Conversations settings control how Rational AI enriches and processes end-user conversations behind the scenes. From here you configure four automatic analyses—**title generation**, **topic detection**, **sentiment analysis** and **summary generation**—each of which can be enabled independently and assigned its own model and prompt. You also define the **human oversight** rules that flag conversations for review, and the **statuses** a conversation can have.

The model that writes the replies users see isn't set here: it's the **Conversational model** default in the [AI Model Registry](/operational-guides/ai-model-registry-features#set-default-platform-models-per-task-type), unless a [touchpoint](touchpoints.mdx) picks its own.

## Choosing a model for each analysis

Every analysis has its own model picker. Besides the models in the registry, the picker offers two defaults:

* **Platform default model** – Use the platform's **Conversational model**, set in the [AI Model Registry](/operational-guides/ai-model-registry-features#set-default-platform-models-per-task-type).
* **Touchpoint default model** – Use the model of the touchpoint the conversation belongs to. This is also what an empty picker means.

A specific model you pick always wins over both defaults. If the default you chose resolves to no model, that analysis is skipped for the conversation.

## Title generation settings

When enabled, Rational AI automatically generates a short title for each conversation so it's easy to recognize later.

* **Enable title generation** – Turn the feature on or off.
* **Title generation model** – The model used to produce the title.
* **Calculation frequency** – How many messages to receive before a title is generated (for example, *every 1 message*).
* **Number of messages to consider** – The number of most recent messages used to generate the title.
* **Title generation template prompt** – The instruction sent to the model, returning the title as a JSON object. **Restore default** brings back the shipped prompt.

## Topics detection settings

When enabled, each conversation is tagged with up to three topics from a defined list—useful for filtering, reporting and routing.

* **Enable topic detection** – Turn the feature on or off.
* **Topics detection model** – The model used to classify the conversation.
* **Calculation frequency** – How many messages to receive before topics are detected.
* **Number of messages to consider** – The number of most recent messages used for classification.
* **Topic list** – The set of allowed topics (for example, *Order Status*, *Billing Request*, *Tech Support*). Remove a topic with its **×**, or add your own with **New**.
* **Topic detection template prompt** – The instruction sent to the model. The model returns the matching labels, written exactly as they appear in the topic list, as a JSON object. **Restore default** brings back the shipped prompt.

## Sentiment analysis settings

When enabled, Rational AI estimates the emotional tone of incoming messages, so urgent or negative conversations can be prioritized.

* **Enable sentiment analysis** – Turn the feature on or off.
* **Sentiment analysis model** – The model used to calculate the sentiment of users' messages.
* **Calculation frequency** and **Number of messages to consider** – As for titles and topics.
* **Sentiment list** – The sentiments the model can choose from, each with its own label and color. Add one with **New sentiment…**.
* **Sentiment analysis template prompt** – The instruction sent to the model, with **Restore default**.

## Summary generation settings

When enabled, operators can generate a structured summary of a conversation to review before taking it over.

* **Enable summary generation** – Turn the feature on or off.
* **Summary generation model** – The model used to write summaries. Thinking models are not recommended for this task.
* **Number of messages to consider** – How many of the latest messages to include (`0` means all).
* **Summary generation template prompt** – The instruction sent to the model, with **Restore default**.

## Human oversight

When enabled, conversations that match your rules are flagged **Needs review** and stay flagged until someone records a decision on them.

* **Enable human oversight rules** – Turn the feature on or off.
* **Rules** – One or more condition groups. Use **Add condition group** and **Add condition** to describe the conversations that need a human.

See [Record oversight decisions](/operational-guides/human-oversight) for what reviewers do with a flagged conversation.

## Conversations status

Define the stages of a conversation and how they appear in the conversation list. Type a new status in **Type new…**, and mark the ones that end a conversation as **Closed status**. A status that conversations still use can't be deleted.

Use **Save** to apply your changes to the analyses and rules, or **Cancel** to discard them.

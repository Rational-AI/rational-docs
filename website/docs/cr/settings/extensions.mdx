# Extensions

Extensions add new capabilities to Rational AI. Depending on the one you install, an extension can give your agents new **tools** to use in a conversation (such as fetching a web page, querying a database or searching the web), **skills** they can draw on, a **channel** for users to message the assistant (like Telegram), a **source** your Knowledge bases sync files from, or a **workflow** that processes incoming files. The [Marketplace](/operational-guides/marketplace) solutions are extensions too: installing one can also create a Knowledge base with its views and records, agents, BI dashboards and a website widget. Use this section to install extensions from the catalog or from your own package files, enable or disable them, configure their settings and review what each one provides. To build your own, see [Build an extension](/operational-guides/build-an-extension); to keep the ones you have current, see [Update and roll back extensions](/operational-guides/extension-updates).

## Browse installed extensions

The Extensions page lists every installed extension as a card on the left. Each card shows the extension's name and icon, a toggle to enable or disable it, and counters summarising the capabilities it provides.

* **Search** – Use the search box above the list to filter extensions by name.
* **Select** – Click a card to open its details in the panel on the right.

Selecting an extension shows its description and the capabilities it provides. When an extension provides tools, you'll also see the number of **tools provided** and a card for each tool with its name and a short description of what it does.

## Add an extension

Click **Install** in the top-right corner to browse the extensions you can install. From here you can:

* **Search** for an extension by name.
* **Select** an extension to install (for example, Telegram, Fetch, GitHub, Postgres, Brave Search or Time).

The extensions on offer come from more than one place: the **platform catalog** that Rational AI publishes, your own **local packages** (anything you installed from a file by dropping it onto this page), and any remote source attached for your organization. You can also install your own package at any time by dragging it onto the Extensions page.

## Configure an extension

Installing never asks for configuration up front. An extension that still needs values from you lands **installed and disabled**, with nothing running. Install it now, set it up when you have the credentials.

Saving its first configuration is what starts the extension: the MCP server starts, its tools are discovered, and the extension is enabled. If a required value is missing, the save is refused with a validation error and the extension stays disabled, so nothing ever half-starts. An extension whose values all have defaults comes up enabled immediately, with no extra step.

## Develop an installed extension

Administrators see a **Development** tab on an installed extension. Use it to
enable file editing for this installation, edit and **Save and apply** files,
**Download installed extension** for local work, or disable development to
return to normal package updates. The
[development guide](/operational-guides/develop-an-extension) explains remote
edits, Git recovery and resuming package updates when you leave development.

## Enable or disable an extension

Use the toggle on each extension card to turn it on or off. A disabled extension stays installed and keeps its configuration, but its tools are not available to agents until you re-enable it. This is useful for temporarily taking an extension out of service without uninstalling it.

## Manage an extension

With an extension selected, open the options menu (the three vertical dots) in the details panel to access:

| Action | Description |
|--------|-------------|
| **Settings** | View and edit the extension's configuration (for example, credentials or connection details). |
| **Update policy** | Choose how updates reach this extension: **Compatible updates automatically** applies compatible updates for you, **Notify me** (the default) lists them and applies nothing, and **Pinned** holds the extension on its exact version. |
| **Update** | Move the extension to a newer release when one is available. Disabled when the extension is already up to date, and replaced by *"Pinned — change the update policy to install updates"* while the extension is pinned. |
| **Uninstall** | Remove the extension, its MCP servers, its configurations and its tools. Touchpoints that used its tools survive and lose those bindings, and re-installing the same package later comes up clean. |

For what "compatible" actually means, what happens to your touchpoints when an update lands, and how to roll back, see [Update and roll back extensions](/operational-guides/extension-updates).

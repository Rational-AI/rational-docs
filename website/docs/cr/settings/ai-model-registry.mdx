# AI Model Registry

It’s the central catalog of the AI models you can use in Rational AI. You add a model once and use it everywhere: chats, touchpoints, Knowledges and workflows. The registry also controls which models are available, runs the models you host yourself, and records what each one costs and who approved it. Open it from **Settings** → **AI Model Registry**.

Select **Add new** to add one of three kinds of model.

### Choose an open source model

* Select **Choose an open source model**. The list is searched live on Hugging Face.
* Sort by **Best match**, **Most downloads**, **Most likes** or **Recently updated**, and filter by **Formats**, **Curated picks** or **Only models that fit**. Only the formats your hosting platform can run are offered.
* Select a model to read its card: publisher, architecture, parameters, weights and its Hugging Face model card.
* Click **Confirm**. The model is added; deploy it from its **Deployment** section.

See [Deploy and run self-hosted models](/operational-guides/model-deployments) for the whole flow.

### Install your own fine tuned model

Shown only where your hosting platform accepts uploaded weights (not on on-premises installations).

* Choose **Install your own fine tuned model**.
* Pick the model file (`.gguf`) and check the **Name**.
* Click **Confirm**. The file is uploaded and the model deployed.

### Add a proxy to a third-party model

* Choose **Add a proxy to a third-party model** (*"Connect to OpenAI, Gemini, Claude and others with your API Key"*).
* Pick the connector and the provider's model, and give it a name.
* Click **Confirm**.

## Manage models

Each row's menu offers:

| Action | What it does |
|---|---|
| **See details** | Opens the model's drawer: overview, deployment, payload tracing, governance, usage |
| **Edit details** | Name, model identifier, description, capabilities, reasoning levels, deploy settings, inference defaults and cost metering |
| **Test model** | Sends a test request to a ready model; it never deploys one |
| **Deploy model**, **Stop model**, **Resume model** | Control a self-hosted model's deployment |
| **Disable** / **Enable** | Take a model out of service at once, or bring it back |
| **Delete** | Removes the model, offering to move its uses to another model first |

The **Status** column shows a self-hosted model's deployment phase (for example **Ready**, **Idle**, **Stopped**, **Failed**) and **Disabled** for a disabled model. A model with billing history cannot be deleted: disable it instead.

For capabilities, image capabilities, default models and approval, see [Manage AI models in the registry](/operational-guides/ai-model-registry-features).

## Cost metering

### Enable cost metering (toggle)

In **Edit details**, **Cost metering** turns cost tracking on or off for the model.

* On: the model's spending is reported in the Governance module.
* Off: the model still works, but Rational AI does not track its costs.

### Pricing components

With cost metering on, add every **Pricing component** that applies, in the chosen **Currency**: cost per request, per image, per web search, per million input, output and reasoning tokens. Empty fields are treated as unknown, not free. Third-party models may show **Provider catalog pricing**, synchronized from the provider.

For self-hosted models, **Infrastructure billing** adds the cost of the hardware: **No infrastructure charge**, **Only while a deployment is active**, or **Reserved capacity (continuous)**, at an **Infrastructure rate** per hour, minute or second.

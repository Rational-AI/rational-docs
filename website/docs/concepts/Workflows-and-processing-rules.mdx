# Workflows and processing rules

**Workflows** and **processing rules** are how you automate work in the platform. A **workflow** is a sequence of steps that runs to accomplish a task, while a **processing rule** is the conditional logic that decides what should happen in a given situation. Loosely: the workflow is the recipe, and the processing rules are the "if this, then that" decisions inside it.

Together they let the platform do more than answer single questions. They turn AI into something that can carry out multi‑step jobs and react to your data automatically.

## Workflows

A workflow chains several steps into one automated process that turns raw files into structured information: converting a document, extracting attributes, annotating it, linking it to other resources. Each step feeds the next, so a workflow can accomplish something no single step could on its own.

In Rational AI a step is a Python script, and a workflow is a graph that connects steps, control-flow nodes and built-in operations. You edit the graph as code or on a canvas. A Knowledge runs its default workflow on every file added to it.

## Processing rules

A processing rule expresses a decision: which processing to run for a given file, based on its document type, content, source or any custom condition. It is a router. It doesn't change the data itself; the step it picks does the work. That is what lets a Knowledge handle an invoice and a technical manual differently instead of treating every input the same way.

## How they work together

In a Knowledge, the two meet in the **Sources** settings. The **Default workflow** is either a workflow graph or the **Classic pipeline**. With the classic pipeline, the **Default processing rule** picks the step for each file, and each attached source can use its own processing rule. You can also assign a workflow to single files from the Knowledge's **Files** view.

## In Rational AI

You manage both in **Settings** → **Workflows**, which has a **Workflows** tab (workflow graphs and steps) and a **Processing rules** tab. See the operational guides on how to [create a workflow](../operational-guides/create-workflow.mdx) and how to [create a processing rule](../operational-guides/create-processing-rule.mdx).

# Workflows and processing rules

Steps, workflows, and processing rules decide what happens to each file a Knowledge receives: what is extracted from it, which resources it becomes, and what text is chunked and embedded for search. You manage all three in **Settings** → **Workflows**.

## Steps

A step is one Python script that does the work on a file. It reads the file, creates resources in the Knowledge, and returns the text to chunk and embed.

## Workflows

A workflow is a graph that connects steps, control-flow nodes, and built-in operations, so one file can go through several steps in order or take different branches. You build it on a canvas or in code. A Knowledge runs its **Default workflow** on every file added to it.

## Processing rules

A processing rule is a Python script that returns the name of one step for each file, based on its name, type, content, source, or any condition you write. It routes the file and doesn't change it. This is how one Knowledge can send invoices to one step and technical manuals to another.

## How they meet in a Knowledge

On a Knowledge's **Sources** tab, **Default workflow** is either a workflow or the **Classic pipeline**:

- With a workflow, the graph handles every file.
- With the **Classic pipeline**, the **Default processing rule** picks the step for each file. Each attached source can use its own **Processing rule** instead.

In the Knowledge's file list, **Assign workflow** sets the step for the selected files directly. It applies the next time those files are processed.

- [Create a workflow](/operational-guides/create-workflow): write steps and connect them into a workflow.
- [Create a processing rule](/operational-guides/create-processing-rule): pick the step for each file.

# AI model registry

An **AI model registry** is a central catalog of the models an organization can use. Rather than wiring each model into each application separately, you register a model once and then reference it everywhere it is needed.

Think of it as a library with a card catalog. The models are the books; the registry is the system that records what you have, where each one lives and who can borrow it. Without it, every team ends up with its own shelf and no one is sure which copy is current.

## Why a registry matters

As soon as more than one model is in play, a few problems appear: which models are approved, which version is live, what each one costs, and who is allowed to use it. A registry answers these in one place and gives you:

* **Consistency:** the same model, referenced the same way, across chat, agents, tools and workflows.
* **Control:** a single point to decide which models are available and which are approved for use.
* **Visibility:** key information such as type, size and last update, kept together.
* **Maintainability:** the ability to add, swap or retire models without rewiring everything that uses them.

## Models come in types

A registry typically holds more than one kind of model, because different jobs need different [architectures](/reference/glossary#model):

* **Generative models** that produce replies.
* **Embedding models** that turn text into vectors for retrieval.
* **Reranking models** that reorder retrieved passages by relevance.
* **Image generation models** that draw pictures from a prompt.

Rational AI's registry also holds **Decision** models, which return a structured answer instead of prose. Keeping them all in one catalog is what lets a [RAG](./RAG.mdx) system combine retrieval and generation cleanly.

## The AI Model Registry in Rational AI

In the platform, the [AI Model Registry](../cr/settings/ai-model-registry.mdx) is where you add models once and reuse them consistently across the product. You control which models are available, see their key details, and manage changes over time. Models you create through [fine-tuning](./Finetuning.mdx) appear here too once you deploy them, alongside the base models you registered.

# Personalizza il pannello dei dettagli utente

Aggiungi i tuoi dati su un utente, come i suoi ordini o il livello fedeltà, al pannello **Dettagli** delle sue conversazioni in **Conversazioni**. Alleghi i dati e un web component che li mostra al record utente tramite la Management API. Gli operatori vedono così il contesto di business accanto alla chat.

## Come il pannello mostra i tuoi widget {#how-the-panel-renders-your-widgets}

Apri una conversazione in **Conversazioni** e seleziona **Dettagli** nella sua intestazione. Il pannello mostra questi campi della conversazione: **Utente**, **Touchpoint**, **Stato**, **Sentiment**, **Avviata**, **Ultimo messaggio**, **Messaggi**, **ID**, **Argomenti** e **Riepilogo**.

Sotto questi campi, il pannello mostra i widget dell'utente dietro la conversazione. Due campi del record utente li governano:

| Campo | Tipo | Scopo |
|---|---|---|
| `context` | Oggetto JSON | I dati: chiavi e valori liberi, come `loyaltyTier` o `orders` |
| `contextConfiguration.widgets` | Lista | I widget che mostrano i dati |

Ogni widget è un [custom element](https://developer.mozilla.org/en-US/docs/Web/API/Web_components) definito da uno script che tu ospiti. Una definizione di widget ha:

- `tagName`: il custom element da creare, per esempio `orders-list`.
- `url`: lo script che definisce l'elemento.
- `inputs`: le proprietà da impostare. Per ogni `{ "name": "orders" }`, il pannello imposta la proprietà `orders` dell'elemento su `context.orders`. Il campo facoltativo `type` è un suggerimento e non viene verificato.

Per ogni widget, il pannello carica lo script, a meno che un elemento con quel tag non sia già definito. Poi crea l'elemento, ne imposta gli input e lo aggiunge al pannello. Il tuo componente decide come appaiono i dati.

Una conversazione con un visitatore anonimo non ha un record utente, quindi non mostra widget.

## Prima di iniziare {#before-you-begin}

- **Modifica** sulla riga **Utenti** del tuo ruolo, o un account amministratore. Vedi [Gestisci ruoli e utenti](/operational-guides/roles-and-users).
- Una chiave API. Vedi [Accedi a Rational AI tramite API](/operational-guides/api-access#create-an-api-key).
- L'ID dell'utente da personalizzare, e il suo nome e cognome attuali.
- Un luogo dove ospitare un file JavaScript che i browser degli operatori possano caricare via HTTPS.

Lo script del widget viene eseguito dentro la pagina della Control Room, con la sessione dell'operatore che apre la conversazione. Carica solo script che controlli tu.

## Costruisci il widget {#build-the-widget}

1. Scrivi un custom element che legge i suoi dati da una proprietà. Questo mostra un array `orders`:

   ```js
   // orders-list.js
   class OrdersList extends HTMLElement {
     // The panel sets this property from context.orders
     set orders(value) {
       this._orders = value ?? [];
       this.render();
     }

     render() {
       this.innerHTML = `
         <h2>Recent orders</h2>
         <ul>
           ${this._orders.map((o) => `<li>${o.name} (<code>${o.sku}</code>)</li>`).join("")}
         </ul>`;
     }
   }

   customElements.define("orders-list", OrdersList);
   ```

2. Ospita il file, per esempio su `https://cdn.example.com/widgets/orders-list.js`.

Il nome di un custom element deve contenere un trattino ed essere unico nella pagina. Se due widget usano lo stesso tag, il pannello carica solo il primo script ed entrambi i widget vengono mostrati con quello.

## Collega i dati e il widget all'utente {#attach-the-data-and-the-widget-to-the-user}

Invia `PUT /api/management/v0/users/{id}` con i nomi dell'utente, i dati in `context` e il widget in `contextConfiguration`:

```bash
curl -X PUT "https://control-room.example.com/api/management/v0/users/$USER_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "givenName": "Jane",
    "familyName": "Doe",
    "context": {
      "loyaltyTier": "Gold",
      "orders": [
        { "name": "Paracetamolo", "sku": "FA-4294953" },
        { "name": "Ibuprofene", "sku": "FA-1485914" }
      ]
    },
    "contextConfiguration": {
      "widgets": [
        {
          "tagName": "orders-list",
          "url": "https://cdn.example.com/widgets/orders-list.js",
          "inputs": [{ "name": "orders", "type": "array" }]
        }
      ]
    }
  }'
```

I tre campi si aggiornano in modo diverso:

- `givenName` e `familyName` sono obbligatori e sostituiscono i nomi salvati. Invia i nomi attuali per mantenerli.
- `context` viene unito: le chiavi che invii vengono aggiunte o sostituite, le altre chiavi salvate restano.
- `contextConfiguration` viene sostituito. Invia ogni volta l'elenco completo dei widget. Se ometti il campo, rimuovi tutti i widget.

La volta successiva che un operatore apre una conversazione con questo utente, il widget `orders-list` compare in fondo al pannello **Dettagli**.

## Risoluzione dei problemi {#troubleshooting}

| Sintomo | Cosa controllare |
|---|---|
| Vengono mostrati solo i campi integrati | L'utente non ha `contextConfiguration.widgets`, oppure la conversazione è anonima. |
| Il widget viene mostrato ma è vuoto | I nomi in `inputs` non corrispondono alle chiavi in `context`, oppure le chiavi non sono state inviate. |
| Il widget non compare mai | Il caricamento da `url` non è riuscito, oppure lo script non definisce il `tagName` dichiarato. La console del browser mostra *"Failed to load widget"* con il nome del tag. |
| I widget sono scomparsi dopo un aggiornamento | L'aggiornamento ha omesso `contextConfiguration`, oppure ne ha inviati solo alcuni. Viene sostituito, non unito. |
| Il nome dell'utente è cambiato dopo un aggiornamento | La richiesta ha inviato altri valori in `givenName` e `familyName`. |
